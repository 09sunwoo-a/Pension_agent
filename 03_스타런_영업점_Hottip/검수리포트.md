# 검수 리포트

수집된 게시글의 본문 정합성 검수 결과와 이미지 수집 방식, 그리고 발견·수정한 변환 오류를
정리한 문서입니다. 텍스트 정합성 검수(1~4절)는 나만의 Hot Tip 49건을 대상으로 하며,
추가 수집한 본부부서 Hot Tip 9737(총 50건째)은 본문이 카드뉴스 이미지 2장으로만 구성되어
텍스트 대조 대상이 아닙니다(이미지 캡처 및 상세 설명 방식은 5절과 동일 기준 적용).

## 1. 검수 방법

원본 HTML에서 이미지 태그를 제거한 순수 텍스트와, 변환된 마크다운에서 구조 문법(글머리 기호,
표 구분선, 굵게/기울임 표시, 이미지 마크다운, 인용 기호 등)을 제거한 순수 텍스트를 각각
공백 제거 후 문자 단위로 비교했습니다 (`tmp/html2md.py`의 `verify()` 함수).

- **완전 일치(exact_match)**: 두 텍스트가 정확히 동일
- **근접 일치(near-match)**: 완전히 같지는 않지만 글자 수 비율(len_ratio)이 매우 높은 경우 —
  전부 아래 3절에서 설명하는 비손실성 서식 차이로 확인됨

## 3. 발견 및 수정한 변환 버그 (2건)

작업 중 아래 2건의 실제 내용 손실 버그를 발견해 `tmp/html2md.py`를 수정하고, 전체 49건을
재변환하여 반영했습니다.

### 3-1. 중첩 표(nested table) 중복 표기 버그

- **증상**: 글번호 201153의 마크다운이 원본보다 훨씬 길어짐(len_ratio 0.4115) — 같은 문장이
  3~4회 반복 표시됨.
- **원인**: 원본 HTML에 `<figure class="table"><table>...<td><figure class="table"><table>...`
  형태로 표 안에 장식용 제목 박스가 중첩 표로 들어있었는데, 표 변환 함수가
  `find_all('tr')` (재귀 검색)를 사용해 중첩된 표의 행까지 바깥 표의 행처럼 이중으로 읽어들임.
- **수정**: 표 태그의 직계 자식 `<tr>`만 순회하는 `_own_rows()` 헬퍼를 추가해 중첩 표를
  건너뛰도록 수정 (`recursive=False`).
- **검증**: 전체 `raw/*.html`에서 표 중첩 패턴을 재검색해 영향 가능 파일 4건(199343, 200911,
  201070, 201153)을 확인. 재변환 후 201153은 완전 일치로 전환되었고, 나머지 3건의 잔여 오차는
  아래 3-3절의 rowspan 중복 표기(의도된 동작)로 확인됨.

### 3-2. figcaption(이미지 출처) 누락 버그

- **증상**: 글번호 199345, 200911에서 원본에는 있는 "연금사업부(기획)169 문서참고" 같은 이미지
  출처 텍스트가 마크다운에서 통째로 빠짐.
- **원인**: `<figure class="image"><img>...<figcaption>...</figcaption></figure>` 구조에서
  이미지 변환 로직이 `<img>`만 처리하고 `<figcaption>`은 무시함.
- **수정**: figure 블록 처리 시 figcaption이 있으면 `> 출처: {내용}` 형식으로 이미지 설명 바로
  아래에 추가하도록 수정.
- **검증**: 재변환 후 199345는 0.9455 → 0.9871로, 200911은 0.9805 → 0.9927로 개선. 남은 차이는
  "출처:" 라벨 자체가 추가된 것으로, 정보 손실이 아닌 정보 보강임.

## 4. 근접 일치의 잔여 원인 (전부 비손실성으로 확인)

- **표 rowspan(세로 병합) 중복 표기**: 마크다운 표 문법은 셀 병합을 표현할 수 없어, 세로로 병합된
  셀의 내용을 하위 행에도 반복해서 채워 넣습니다. 내용이 사라진 게 아니라 오히려 각 행에서 어떤
  값이 적용되는지 더 명확히 보이도록 중복 표기한 것으로, 의도된 동작입니다. (201070, 199343,
  200911 등 표가 많은 게시글에서 주로 발생)
- **`<strong>` 안에 이미지가 포함된 경우의 굵게 표시 흔적**: 원본에서 굵은 글씨 스타일 안에
  이미지가 포함된 경우, 마크다운 변환 시 `**` 기호가 이미지 마크다운 앞뒤에 약간 남는 경우가
  있습니다. 시각적으로 사소한 서식 흔적이며 본문 내용은 그대로입니다. (199381 등)
- **원문 자체의 수동 번호 매기기와 마크다운 자동 번호 매기기 중복**: 원본 리스트 항목에 저자가
  이미 "1.", "2." 같은 번호를 직접 입력한 경우, 마크다운의 정식 순서목록(`1.`, `2.`)으로 다시
  인식되어 검증 스크립트가 이를 구조 문법으로 제외하면서 글자 수가 약간 어긋나 보이는 경우입니다.
  원본 파일을 직접 대조한 결과 내용은 모두 그대로 들어있습니다. (199713, 198873 등)

이상 세 가지 원인 모두 **실제 텍스트 내용의 누락이 아닌, 마크다운 표현 방식의 차이**로 확인되어
별도 수정 없이 그대로 두었습니다.

- 총 이미지 개수: **221장** (49건 게시글 중 이미지가 없는 11건 제외, 38건에 이미지 포함)

## 6. 결론

49건 전체에 대해 본문 내용 손실은 확인되지 않았습니다. 초기 자동 검수에서 발견된 오차는 모두
원인을 규명했으며, 그중 실제 버그였던 2건(중첩 표 중복, figcaption 누락)은 수정 후 전체
재변환·재검증을 완료했습니다. 나머지 근접 일치 24건의 잔여 오차는 마크다운 문법 자체의 표현
한계(표 병합 셀 중복 표기 등)로, 본문 내용은 모두 원본과 동일하게 보존되어 있습니다.
