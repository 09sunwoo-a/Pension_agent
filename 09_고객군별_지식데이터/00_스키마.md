# 00. 스키마 정의 — 고객군별 지식데이터 규격

> 작성 2026-08-23 · 대상 고객군 6종 · 원천: `06_주제별_추출지식/` 5개 축 + `07_에이전트_기능정의/`

## 이 문서는

6개 고객군(①수익률 저조 ②자산편중 ③방치 ④이탈가능성 높음 ⑤세액공제·추가입금 ⑥예금·GIC 만기예정)에 대해
**에이전트가 그대로 읽어 동작할 수 있는 정규화 규격**을 정의합니다.
`06_주제별_추출지식`이 "팀이 채택/제외를 결정하는 리뷰 문서"였다면, 이 폴더는 **채택 결과를 기계가 읽는 형태로 옮긴 데이터**입니다.

## 설계 원칙 5가지

1. **한 지식은 한 곳에만 둔다 (중복 제거)** — 같은 화법·팩트가 여러 고객군에 쓰이면, 지식유닛은 `20_지식유닛.yaml`에 **1건만** 두고 각 고객군이 ID로 참조한다. 수정 지점이 하나여야 수치 갱신 사고가 안 난다.
2. **모든 레코드는 같은 필드 집합을 갖는다** — 고객군마다 다른 구조를 쓰지 않는다. 필드가 비면 `null`로 두고, 왜 비었는지는 `open_questions`에 적는다.
3. **수치에는 반드시 기준시점(`as_of`)이 붙는다** — 기준시점 없는 수치는 데이터로 넣지 않는다(`07_에이전트_기능정의` 원칙 4).
4. **신뢰·공개등급을 모든 레코드에 표시한다** — 본부공식인지 현장팁인지, 고객에게 그대로 보여도 되는지(`disclosure`)를 지식유닛 단위로 표시한다(원칙 5).
5. **"하지 말 것"을 데이터로 넣는다** — 금지 용어·권유 제외 대상·계좌 상태 제약을 `guardrail` 유형의 지식유닛으로 1급 시민으로 둔다(원칙 6).

## 1. 엔티티 `segment` (고객군)

에이전트가 "이 고객이 대상인가"와 "왜 지금인가"를 판단하는 단위.

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | string | ● | `SEG-01` ~ `SEG-06` |
| `name` | string | ● | 고객군 이름 |
| `aliases` | string[] |  | 원천 자료에서 쓰이는 다른 이름 |
| `one_line` | string | ● | 한 줄 정의 (브리핑 "왜 지금" 칸의 원료) |
| `business_goal` | enum | ● | `수익률제고` / `이탈방어` / `자금유입` / `관리사이클` (복수 가능) |
| `population.base` | string | ● | 모집단 (예: 당행 개인형IRP 보유 고객) |
| `population.include` | rule[] | ● | 포함 조건. 각 rule은 `{field, op, value, as_of, source}` |
| `population.exclude` | rule[] | ● | 제외 조건 (컴플라이언스·상태 제약 포함) |
| `threshold_variants` | variant[] | ● | **자료 간 임계값이 다를 때 전부 적재한다.** `{value, source, as_of, purpose, adopted}` — `adopted: true`가 권장 기본값 |
| `recommended_target` | object | ● | **타겟 축소용 권장 기본 조건** — `{rule, expected_scale, rationale}` |
| `false_positive_filters` | filter[] | ● | 오탐 제거 조건 (접촉 전 확인) |
| `priority.sort_keys` | string[] | ● | 접촉 우선순위 정렬 키 |
| `priority.scoring` | object |  | 요건 충족수 기반 가중 (있을 때만) |
| `data_requirements` | string[] | ● | 타깃 추출에 필요한 데이터 필드 |
| `lookup_screens` | screen[] | ● | 사전 조회 화면 `{code, name, purpose}` |
| `why_now` | evidence[] | ● | 접촉 명분이 되는 근거 수치 `{claim, number, as_of, ku}` |
| `kpi_link` | object |  | 실적 인정 요건 (있을 때만) |
| `briefing_slots` | object | ● | `07_에이전트_기능정의` ① 브리핑 7칸에 무엇을 채우는가 |
| `offers` | offer[] | ● | 제안 카드 (우선순위순) `{rank, action, ku, condition}` |
| `knowledge_units` | ref[] | ● | 참조 지식유닛 ID + 이 고객군에서의 역할 |
| `scenarios` | ref[] | ● | 참조 시나리오 ID |
| `guardrails` | ref[] | ● | 참조 금지·주의 지식유닛 ID |
| `followup` | object | ● | 후속 예약 규칙 `{trigger, interval, action}` |
| `open_questions` | string[] | ● | 팀·본부 확인이 필요한 미결 사항 |

### rule 표현식 규격

```yaml
- field: 고유계정대_보유비율      # 데이터 딕셔너리 용어
  op: ">="                      # >= <= == != in between exists
  value: 0.50
  as_of: "2026.05"              # 이 조건이 규정된 시점
  source: KU-E-001              # 근거 지식유닛
```

`op: between`은 `value: [min, max]`, `op: in`은 `value: [...]`로 쓴다.
조건 간 결합은 기본 AND이며, OR이 필요하면 `any_of: [rule, rule]`로 감싼다.

## 2. 엔티티 `knowledge_unit` (지식유닛)

원자적 지식 1건. **여러 고객군이 공유하며, 본문은 여기에만 존재한다.**

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | string | ● | `KU-<유형코드>-<3자리>` |
| `type` | enum | ● | `fact` / `method` / `script` / `procedure` / `evidence` / `guardrail` |
| `title` | string | ● | 제목 (그 자체로 내용을 읽을 수 있게) |
| `segments` | string[] | ● | 적용 고객군 ID 목록 |
| `trigger` | string | ● | 이 지식이 발동하는 상황 또는 고객 발화 |
| `branch` | branch[] |  | 조건 분기 `{condition, body}` — script 유형에서 특히 중요 |
| `body` | text | ● | 본문. script는 **그대로 읽을 수 있는 완성 대사**로 쓴다 |
| `numbers` | number[] |  | 인용 수치 `{label, value, as_of, verify}` |
| `screens` | string[] |  | 관련 화면번호 |
| `cautions` | string[] |  | 사전 고지·주의 문구 |
| `source` | object | ● | `{doc, section, org, date}` |
| `origin_ref` | string | ● | `06_주제별_추출지식` 원 항목 번호 (역추적용) |
| `trust` | enum | ● | `본부공식` / `현장팁` / `대외공개` / `정리자해석` |
| `disclosure` | enum | ● | `대고객가능` / `표현변경후` / `사내전용` |
| `status` | enum | ● | `확정` / `기준시점병기조건부` / `검증필요` |
| `confidence` | enum | ● | `high` / `medium` / `low` |
| `related` | string[] |  | 함께 쓰는 지식유닛 ID |

### 유형별 필수 추가 규칙

- **`fact`** — `numbers`와 `as_of` 필수. 기준시점 없는 수치는 `status: 검증필요`.
- **`script`** — `body`는 지시문이 아니라 **대사**여야 한다. "안내하세요" ❌ → "고객님, …입니다" ⭕
- **`procedure`** — `screens` 필수. 단계는 번호를 매기고, 중단 시 절반 처리가 되는 지점에 `cautions`를 붙인다.
- **`guardrail`** — `body`에 금지 행위와 대체 행위를 한 쌍으로 쓴다.
- **`evidence`** — `why_now`에 인용되는 근거 수치. 출처와 모집단·기간을 반드시 적는다.

## 3. 엔티티 `scenario` (케이스 시나리오)

한 고객군 안에서 **고객 상태·응답에 따라 갈리는 진행 경로**. 에이전트가 상담을 끌고 가는 골격.

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | string | ● | `SC-<세그먼트번호>-<분기코드>` (예: `SC-02-A`) |
| `segment` | string | ● | 소속 고객군 |
| `name` | string | ● | 시나리오 이름 |
| `entry_condition` | rule[] | ● | 이 경로로 들어오는 조건 |
| `qualifying_questions` | question[] | ● | **분기 조건을 뒤집은 질문지** — `{ask, branches}` |
| `turns` | turn[] | ● | 진행 턴 `{step, actor, say(ku), purpose}` |
| `objection_cards` | ref[] | ● | 이 경로에서 나올 법한 반론 카드 |
| `success_action` | object | ● | 합의 시 처리 — `{cart_items, procedure_ku, memo_template}` |
| `partial_action` | object | ● | 부분 합의·보류 시 처리 |
| `fail_action` | object | ● | 거절 시 처리 (여지 남기기 + 재접촉 예약) |
| `prohibited` | ref[] | ● | 이 경로에서 하면 안 되는 것 |
| `expected_conversion` | object |  | 기대 전환율 기준선 (있을 때만) |

`qualifying_questions`는 `07_에이전트_기능정의` ②의 "판별 질문 = 분기 조건" 원칙을 따른다 —
분기 조건이 있으면 반드시 그것을 고객에게 물을 질문으로 뒤집어 적는다.

## 4. 열거형(enum) 사전

| 필드 | 값 | 의미 |
|---|---|---|
| `trust` | `본부공식` | 연금사업본부·연금컨설팅부 배포자료 |
| | `현장팁` | 스타런 Hot Tip 게시글 (개인 경험 포함) |
| | `대외공개` | KB Think 등 준법감시인 심의필 |
| | `정리자해석` | 원자료에 없는 추론 — **팀 검증 전 대고객 사용 금지** |
| `disclosure` | `대고객가능` | 고객에게 그대로 제시 가능 |
| | `표현변경후` | 내용은 맞으나 표현을 다듬어야 함 (타사 비교·내부용어 등) |
| | `사내전용` | 대외비·KPI·직원 득점 논리 — 고객 앞 언급 금지 |
| `status` | `확정` | 그대로 사용 |
| | `기준시점병기조건부` | 기준시점을 붙여야만 사용 |
| | `검증필요` | 본부·원본 대조 전 인용 금지 |
| `business_goal` | `수익률제고` `이탈방어` `자금유입` `관리사이클` | 고객군의 1차 목적 |

## 5. ID 부여 규칙

| 엔티티 | 형식 | 예 |
|---|---|---|
| 고객군 | `SEG-NN` | `SEG-04` |
| 지식유닛 | `KU-X-NNN` (X: F팩트 / M방법론 / S화법 / P절차 / E근거 / G금지) | `KU-S-012` |
| 시나리오 | `SC-NN-A` | `SC-06-B` |
| 반론카드 | 지식유닛 중 `type: script` & `trigger`가 고객 발화인 것 | `KU-S-001` |

**ID는 재사용하지 않는다.** 폐기 시 레코드를 지우지 말고 `status: 폐기`와 사유를 남긴다 — 에이전트 로그의 역추적이 끊기지 않게.

## 6. 갱신 규칙

| 갱신 주기 | 대상 | 처리 |
|---|---|---|
| 매월 | 원리금보장 특별제공상품 금리, 고유계정대 금리, 추천펀드 | `fact` 유닛의 `numbers.value`·`as_of` 갱신. 값을 하드코딩한 `script`는 금지 — script는 `{금리}` 슬롯만 갖는다 |
| 매분기 | 수익률 공시·순위, 환매추천펀드 목록 | `as_of` 갱신 + 기준분기 표기 확인 |
| 반기 | KPI 인정 요건 | `kpi_link` 갱신, 실효 시 `status: 폐기` |
| 수시 | 화면번호·제도 변경 | `procedure` 유닛 갱신 |

`script` 유형은 수치를 본문에 박지 않고 **슬롯(`{}`)으로 비워 둔다.** 원천 자료(Series1 Mission 2)가 이미 `x.xx%`로 비워 둔 방식과 같다.
