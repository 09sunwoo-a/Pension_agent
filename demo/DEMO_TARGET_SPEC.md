# Demo Target Specification

현재 Demo HTML(`76352690-_____AI______standalone.html`, 화면 제목 «퇴직연금 사후관리 에이전트»)에
실제 구현된 것을 기준으로 정리한다. 값·문구는 HTML AS-IS다. 해석이 들어간 곳은 `Case Intent` 로 표시한다.

## 1. Service Purpose

HTML AS-IS로 확인되는 서비스의 목적:

- **영업점 직원용** 화면이다. 헤더에 부점명 «여의도종합금융센터», 상단에 «오전 7:30 · IRP 고객 1,247명
  분석 완료» 가 고정 표시된다. 고객이 보는 화면이 아니다.
- **오늘 관리할 IRP 고객을 확인**한다. «오늘의 부점 브리핑 · 9월 4일 금요일» 과 «오늘의 중점관리 고객 ·
  15명» 리스트가 대시보드의 본문이다.
- **고객별 AI 브리핑**을 제공한다. 고객을 클릭하면 «AI 분석 · 2026.09.04 기준 분석» 카드가 고객 상황 →
  확인할 점 → 관리 방향 및 제안 → 상담 Point → TIP & 실행 순서로 열린다.
- **상담 중 실시간 Agent 지원**을 한다. 우측 패널 «실시간 상담 · {고객명}» 에서 추천 질문을 누르거나
  직접 입력하면 근거·출처가 붙은 답변이 나온다.
- **상담 후 실행 / Follow-up** 을 연결한다. 실행 화면 번호(예 `[01-12-213] 입금/입금예약`)로 «화면 열기»,
  발송 화면 `[75-08-110]` 열기, 상담 요약 «쪽지» 발송 CTA가 있다.
- «생성 로직» 버튼이 여는 다이어그램(HTML 내장 PNG)에 서비스가 스스로를 설명한 문장이 있다:
  «부점 IRP 고객 데이터에서 오늘의 부점 브리핑과 중점관리 고객까지», 단계 «① 고객 데이터 → ② 고객
  Signal · 고객군 변화 분석(BATCH) → ③ 영업 Resource 탐색(LLM) → ④ LLM 종합 판단 → ⑤ 직원용
  Output(AI 부점 브리핑 · 오늘의 중점관리 고객 15명)».

HTML에 없는 기능(예: 실제 LMS 발송, 실데이터 조회, 다중 부점)은 여기 적지 않는다.

## 2. Main User Flow

HTML에서 실제로 동작하는 흐름:

```text
Intro Splash («오늘의 분석을 불러오는 중», 약 4초)
→ Dashboard
   · 오늘의 부점 브리핑 (고정 문구) · «생성 로직» 다이어그램
   · 오늘의 사후관리 현황 (부점 전체 / 내 담당)
   · KPI 카드 3종 = 필터 (신규 선정 · 지속 관리 · 오늘 방문 예정)
   · 오늘의 중점관리 고객 리스트 (관리 필요도 순) · 조건 추출 · 엑셀
   · 상단 검색 (이름 · 고객번호 · 전화)
→ 고객 선택 (행 클릭 또는 검색 결과 클릭)
→ Bridge 화면 («{고객명} 고객 브리핑 준비 … 브리핑 로딩 중», 약 4초)
→ 고객 상세 (좌 2/3)
   · 고객명 [고객번호] + 배지
   · 고객 정보 · IRP 계좌현황 · 운용 현황 자세히
   · AI 분석 (S1~S5)  ← 김서연·이수민·박정호만. 나머지는 «AI 브리핑은 준비 중입니다»
     · S3 운용안 타일 → «운용 후보 보기» 로 상품 후보 펼침
     · S5 «바로가기»(현장 TIP 원문) · «화면 열기 →»(실행 화면)
→ 우측 패널 (1/3)
   · 실시간 상담 챗 (김서연·이수민·박정호) — 추천 질문 → 답변 → 근거 → CTA(발송 화면 / 쪽지)
   · 대응 가이드 챗 (그 외 15명) — 예상 반응 칩 → 대응 방향 · 추천 멘트
→ 상단 «오늘의 큐 완료 x/y» 로 복귀 · «다음 고객» 으로 이동
→ 리스트의 체크박스로 «처리완료» 표시
```

### 3.2 오늘의 부점 브리핑 (마크업 고정 텍스트)

> 오늘의 부점 브리핑 · 9월 4일 금요일 — 전일 대비 **ISA 만기 예정 고객 3명이 신규 관리대상**으로
> 선정됐습니다. 현재 KB스타뱅킹에서 **ISA 만기자금의 IRP 전환 관련 이벤트**가 진행 중인 만큼, 해당
> 고객군을 우선 확인해 만기자금 활용계획을 점검하고 이벤트를 함께 안내해 보세요.
> (출처 표기) 전일·금일 고객상태 및 관리신호 분석 · 09.04 07:30 기준

- «생성 로직» 버튼 → 내장 다이어그램. 내용: ① 고객 데이터(IRP 운용현황 · 거래·이벤트 · 타 금융자산 ·
  디지털 행동) ② 사전 정의 Signal 태깅(ISA 만기 · 계약이전 · 만기 임박 · 현금성 장기대기 · ETF 조회 ·
  DO 미등록) → 전일 대비 고객군 변화(ISA 만기 예정 +3 · 계약이전 신청 +2 · 정기예금 만기 임박 +2 ·
  현금성 장기대기 −1) ③ 행내 Resource(이벤트 · 세미나 · 상품) 탐색 ④ 오늘 중요한 관리주제 판단 →
  고객별 관리 우선순위 → 직원 Action 도출 ⑤ AI 부점 브리핑 + 오늘의 중점관리 고객 15명
  (1 김서연 ISA 만기 · ETF 조회 / 2 이수민 만기임박 · 현금성대기 / 3 박정호 퇴직급여 · 과세이연 / +12명).
- JS에는 다른 브리핑 문구(`BRIEF_SEGS`: «코스피가 주간 4.2% 하락하며 … 성과저조 고객 3명을 먼저
  챙겨보세요»)가 남아 있으나 **마크업에 바인딩되지 않아 렌더되지 않는다**. `TO REVIEW` (Audit C-01).

### 3.4 KPI 카드 = 필터

| 카드 | 라벨 | 고정 숫자 | 실제 필터 결과 |
|---|---|---|---|
| 신규 선정 | 오늘 새롭게 우선관리 | 15명 | 3명 (김서연 · 이수민 · 박정호) |
| 지속 관리 | 오늘도 관리 필요 | 12명 | 12명 |
| 오늘 방문 예정 | 금일 영업점 방문 예정 | 2명 | 2명 (김나연 · 이혜림, «관리 해소» 표시, 클릭 시 토스트 «전일 관리사유가 해소된 고객이에요 — 오늘 조치는 필요 없어요») |

카드 숫자는 고정 텍스트라 «신규 선정 15명» 은 실제 3명과 맞지 않는다. `TO REVIEW` (Audit C-02).

### 3.5 고객 리스트 «오늘의 중점관리 고객 · 15명 · 관리 필요도 순»

렌더되는 행 수는 18(신규 3 + 지속 12 + 처리완료 3). 행 필드:

| 필드 | 소스 | 예 (김서연) |
|---|---|---|
| 고객명 | `DATA.name` | 김서연 |
| 스타클럽 등급 | `QMETA.club` | VIP |
| 관리 단계 라벨 | `QMETA.mg` — 처리완료 건만 «처리완료» 표시 | (표시 없음) |
| 신호 배지 1~2개 | `QMETA.sig` | 타행 ISA 만기 D-3 · ETF 조회 |
| IRP 잔액 | `QMETA.bal` | 4,500만원 |
| 1년 수익률 | `QMETA.ret` (음수 빨강) | +3.1% |
| 공제한도 링 | `TAX[id]` — 납입 비율 % + «잔여 N만» / «소진 완료». 납입 기록 없는 고객은 링 없음 | 44% · 잔여 500만 |
| 좌측 색 바 | `DATA.bar` (amber/red/green/yellow) | amber |
| 완료 체크박스 | `state.done` — 체크 시 흐려지고 하단으로 정렬 | — |

정렬은 `ORD` 고정 순서(김서연 → 이수민 → 박정호 → 김형준 → 박은영 → 이상철 → 정미란 → 강도윤 →
최지현 → 홍성우 → 윤소라 → 조민재 → 문세영 → 배정훈 → 오경숙 → 서정화 → 임태호 → 한가을).

### 3.6 조건 추출 · 엑셀

| 그룹 | 옵션 |
|---|---|
| 트리거 | 전체 · 이탈위험 · 만기·방치 · 운용개선 · 기회 |
| 적립금 | 전체 · 1억 미만 · 1~2억 · 2억 이상 |
| 투자성향 | 전체 · 안정·안정추구 · 위험중립 · 적극·공격 |
| 인원 수 | 전체 · 상위 5명 · 상위 10명 |
| 세액공제 | 잔여 한도 있는 고객만 |

«조건 일치 N명» → «이 조건으로 추출» → 리스트 위에 «내 추출 조건» 칩과 «N명 추출됨». «엑셀» →
토스트 «현재 조건 N명 — 타겟고객_명단.xlsx 다운로드 (모형)».

JS에는 `selHeadTitle`(Headline) · `selMetrics`(Metric 카드) · `selActName`(Action) · `why`(선정 이유)
데이터가 고객마다 있으나 **현재 마크업에 바인딩된 곳이 없다**. 대시보드 행에는 Headline/Metric/Action
이 표시되지 않는다. 값 자체는 seed case 문서 §7 에 «dormant» 로 보존했다.

## 12. Demo Target Principles (Case Intent)

아래는 HTML을 근거로 한 **기획적 해석**이다.

1. **여러 데이터를 조합해 Opportunity를 발견한다.** 당행 IRP + 타행 ISA(김서연), IRP 만기 + 현금성
   대기 + DO 미등록(이수민), 입출금계좌 입금 + 상담이력 + 메뉴 조회(박정호)처럼 계좌 밖 정보를 묶는다.
2. **시한이 있는 이벤트를 앞에 세운다.** D-3 · D-22 · 60일 시한 · «왜 지금?» 이 브리핑의 축이다.
3. **직원이 바로 상담에 쓰게 만든다.** Opening 멘트, 반응별 화법, 복사 버튼, 실행 화면 딥링크.
4. **제도 + 상품 + 현장지식 + 화면을 한 카드에 연결한다.** S2(제도) → S3(상품) → S4(화법) → S5(핫팁·화면).
5. **근거를 드러내고 등급을 구분한다.** 출처 배지·근거 N건·«본부 확정 지침이 아닙니다»·«현장 팁 출처 —
   공식 기준 확인» 처럼 신뢰도 차이를 화면에 남긴다.

   두되, S3에서는 «실제 관심이 확인되는 경우» 라는 조건을 단다.
