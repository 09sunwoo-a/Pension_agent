# DEMO-03 박정호

HTML 내부 id `pjh`. 대시보드 3순위 · «신규 선정».

## 1. Case Concept

`Case Intent` — 58세 안정추구형 고객이 8월 퇴직 후 **퇴직급여 1억 5,000만원을 8/14 당행 일반 입출금계좌로
수령**해 그대로 두고 있고, 8/20 고객센터 콜에서 «당장 쓸 계획은 없는데 어디 넣어둘지 고민» 이라 말한 뒤
**퇴직연금 입금 메뉴를 조회**한 상황을 묶어, **지급일로부터 60일 이내 IRP 재입금 시 퇴직소득세 환급(과세이연)**
을 시한 이벤트로 세운 Case. S3는 «과세이연정보 등록 후 입금» 5단계 처리 순서와 GIC·단기채권형 운용안이고,
S5는 순번이 있는 업무화면 4개다. 실시간 상담은 지난 상담 기억 호출, 재취업 예정 고객의 계좌 3단 구성 노하우
(영업점 현장 노하우 ⚠), 이번 상담 요약을 쪽지로 보내는 실행까지 시연한다.

**q1 «지난 상담에서 무슨 얘기 했지?» — 상담 기억**

- Lead: 2026년 8월 20일에 고객센터 콜 상담이 있었어요. 8월 퇴직으로 퇴직급여 약 1억 5,000만원을 당행 일반
  입출금계좌로 수령했다고 하셨고, 당장 쓸 계획은 없는데 어디에 넣어둘지 고민이라고 하셨어요.
- memoryNote: ※ 지난 상담 기록입니다 — 그때 나눈 이야기이지 지금 기준 값이 아닐 수 있습니다.
- 출처: 상담 이력 / 근거: 상담 이력 기록 · 과거 상담과 에이전트가 남긴 대화 기록 · 2026-08-20 고객센터 콜

**q2 «재취업 예정이면 계좌를 어떻게 나누지?» — 현장 노하우**

## 11. Case Design Intent

`Inference from HTML`:

1. **원장 밖 자금 탐지** — IRP 원장이 아닌 입출금계좌 입금을 트리거로 쓴다.
2. **상담이력 + 디지털 행동 연결** — 콜센터 발화 → 메뉴 조회 순서로 «관심 확인» 을 만든다.
3. **시한성 Event** — 60일 과세이연 시한, «입금 후 약 3주».
4. **절차 중심 브리핑** — 상품보다 처리 순서(등록 후 입금)를 먼저 세우고 업무화면에 순번을 붙인다.
5. **성향 존중 운용안** — 안정추구형 58세 → GIC 중심 + 단기채권형 일부.
6. **상담 기억 · 요약 · 쪽지** — 대화형 에이전트의 memory/summary/action 유형을 한 고객에서 모두 보여준다.
7. **현장 노하우의 등급 표시** — 재취업 3단 구성은 ⚠ «본부 확정 지침이 아닙니다» 로 구분.
