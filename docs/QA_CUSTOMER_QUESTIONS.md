# 고객별 예상질문 QA — 더미 고객 12명

시연 고객 12명 전원에게 **직원이 실제로 물을 법한 말**을 던져 «답이 잘 나오는가»를 보는
대본이다. 시연 대본(`DEMO_SCENARIO.md` · `DEMO_CUSTOMER_SCENARIOS.md` · `DEMO_REVIEW.md`)이
보여줄 장면을 고른 것이라면, 이 문서는 **원장에 있는 값·기록·상태를 고객마다 빠짐없이
묻는 것**이 목적이다. 라이브러리가 다루지 않은 7명(김현수·박지민·이준호·최서윤·한지우·
오세훈·윤가영)은 여기서 처음 묻고, 라이브러리의 5명(정민석·송도윤·김서연·박정호·이수민)은
그쪽과 겹치지 않는 질문으로 채웠다.

> 이 문서는 손으로 쓴다(생성물이 아니다). 질문은 `src/tests/debug/scenarios.py::QA`,
> 턴마다의 «기대»는 같은 파일의 `QA_EXPECT` 에 있다 — 실행기가 질문 아래 그 줄을 붙여
> 찍는다. **기대는 코드가 아는 값으로만 적었다**(원장 · 세션 저장소의 상담 기록 · 성립
> 요건 · 열려 있는 안내 콘텐츠 · 타겟 룰베이스 원문). 문장은 매번 LLM 이 새로 쓰므로
> «그 값이 그 뜻으로 답에 들어 있는가»를 사람이 읽고 판정한다. 채점은 코드가 하지 않는다
> (`reps.py` 머리말 「채점하지 않는다」).

## 실행

```bash
cd src
python -m scripts.prebuild_briefings                       # 먼저 — 브리핑 12편을 미리 만든다(아래 ②)
PENSION_TODAY=2026-09-07 python -m tests.debug.reps qa                    # 12명 83턴
PENSION_TODAY=2026-09-07 python -m tests.debug.reps qa 김현수 윤가영 --why   # 고객 골라서 · 무엇을 찾아봤나
PENSION_TODAY=2026-09-07 python -m tests.debug.reps qa 3 --why --show-llm   # 블록 번호로 · 폐기된 생성문까지
PENSION_TODAY=2026-09-07 python -m tests.debug.reps qa --brief             # 요약표만
```

턴 하나만 따로 볼 때: `python -m tests.debug -c <고객ID> --debug "<질문>"`.

**돌리기 전에 확인할 것 셋.**

① **오늘을 `2026-09-07` 로 고정한다.** 기대에 적은 잔여일수(이준호 만기 D-3 · 오세훈 D-11 ·
이수민 D-19 · 송도윤 ISA D-13 · 한지우 ISA 이틀 경과 · 박지민 연말까지 115일)가 그 날짜
기준이다. `reps` 의 기본 고정값(2026-08-24)으로 돌리면 이수민의 만기 요건이 안 서고(D-33),
한지우의 ISA 가 만기 «전»(D-12)이 되어 기대가 어긋난다. 브리핑 캐시의 지문에도 오늘이
들어가므로(`briefing_store.fingerprint`) ②의 사전 생성도 같은 날짜로 돌린다 — 실제 날짜가
9/7 이면 환경변수 없이 돌린 것과 같다.

② **브리핑을 미리 만든다.** 고객 블록의 첫 턴은 화면을 여는 자리라 브리핑(순차 LLM 11회)을
생성한다. 무료 gemma 키는 분당 토큰 한도가 있어, 이 11회가 한도를 소진하면 **첫 턴의 답변
작성이 429 로 죽는다**(실측 — 김현수 첫 턴 55초 중 46초가 브리핑 생성, 그 직후 compose 가
429 로 «LLM 호출 실패» 안내). `scripts.prebuild_briefings` 를 한 번 돌려 두면 읽어 쓴다.
그래도 429 가 나면 `LLM_RETRY_ATTEMPTS=10` 과 `--pause=20`(턴 사이 20초)으로 돌린다.

③ **상담 기록 픽스처가 그대로인지 본다.** `reps` 는 실행 전후로 `session_data/` 를 통째로
되돌리지만, `tests.debug` CLI 나 Streamlit 으로 연습한 턴은 남는다 — 남으면 「지난 상담에서
무슨 얘기 했지?」가 방금 연습을 «지난 상담»으로 읽는다. `git status src/session_data/` 가
깨끗해야 한다(기록 없는 고객 김현수·김서연·이수민은 파일 자체가 없는 것이 정상).

### 무엇이 어긋났나 — 고칠 자리

에이전트가 «지어낸» 턴은 0 이다. 어긋난 자리는 전부 **재료 쪽**(무엇을 실었나 · 어떻게
표시했나)이거나 **게이트가 맞게 막았는데 답이 비는** 자리다.

1. **안내 콘텐츠 폴백이 «맞춤»으로 나간다 (SY7).** 최서윤은 상태에 걸린 콘텐츠가 0건인
   고객(`suggest.outreach_chips` 가 빈 목록)인데, `outreach` 도구가 화면 ⑨ 의 임박순 폴백
   (EVT-004 · SEM-002)을 «추천 사유»와 함께 실었고 답변이 그것을 «원리금보장·현금성 36% →
   미운용 자금 운용 이벤트가 적합»으로 썼다(36% 는 원장값이라 게이트 통과).
   **고침(2026-09-07).** `consult_agent/tools/outreach.py::_outreach` 가 콘텐츠마다 이 고객 요건과
   맞는지를 추천 질문 칩과 같은 함수(`support.relevant_outreach`)로 판정해, 맞으면
   «요건 일치: <요건 이름>» 을, 아니면 «요건 일치: 없음 — 이 고객 요건과 무관» 을 적고
   추천 사유를 싣지 않는다. 머리말의 «지금 안내할 것 N건»은 맞는 것만 세고, 폴백은 발송
   화면 제안 목록에서 뺀다. 회귀: `tests.test_consult_agent::check_outreach` ⑤.
2. **개발자 메모가 직원 안내로 나간다 (DY5).** 「고객 발송 가능 자료 미등록 — assets.json 의
   customer_facing 확인 필요」(`strategy_agent/engine/pipeline.py:258` 이 `needs_confirm` 에
   넣는 문장)가 `customer` 재료의 «확인 필요»로 실려 «하면 안 되는 것»의 답에 그대로 나갔다.
   사람에게 보일 문장이 아닌 것은 재료에 싣지 않는다.
   **고침(2026-09-07).** 그 문장을 `needs_confirm` 에서 뺐다. 발송 자료가 없는 전략은
   `docs/DEMO_STATUS.md` §1 「발송 자료 미등록 전략」이 센다(`scripts/demo_status`). 회귀:
   `tests.test_engine` 「확인 필요 목록에 저작자용 문장이 없다」. 답변 끝 추천 질문도 함께
   고쳤다 — 안내 콘텐츠가 폴백뿐인 턴에는 «이 콘텐츠를 고객에게 어떻게 안내하지?»를
   띄우지 않는다(`suggest.followup_questions`).
3. **절차 카드 본문의 화면번호를 인용하면 스팬 게이트가 막는다 (SH5 · PJ5 — 두 번 재현).**
   연금개시 절차 카드는 「[06-12-622] → [02-12-221]」 2단계를 본문에 갖는데, 이 턴의 원장에는
   [02-12-221] 화면 카드만 실렸다. 답변이 [06-12-622] 를 화면번호로 쓰자 span 게이트가
   «자료에 없다»로 폐기하고 원문 2건을 폴백으로 냈다(저작 메모 «지식항목 12·13»까지 노출).
   화면 카드 `screen.06-12-622` 는 지식베이스에 있다 — 절차 카드가 가리키는 화면 카드를 함께
   싣거나, 절차 본문에 있는 화면번호는 스팬 대조에서 절차 카드를 출처로 인정해야 한다.
   **고침(2026-09-07).** 원인은 화면번호 판정을 근거 **한 건씩** 하던 것이었다 — 절차 근거
   차례에서는 통과한 [06-12-622] 가 화면 카드 근거 차례에서 «이 근거에 없는 화면»으로
   걸렸다. `nodes/plan.py::_screen` 이 원장 전체의 화면번호 합집합(`_ledger_screens`)을 만들어
   `_span_verdict` 에 넘기고, 화면번호 판정은 그 합집합으로 한다. 지어낸 번호는 여전히
   걸린다. 회귀: `tests.test_consult_agent::check_atomic_spans` 「원장의 다른 근거가 아는
   화면번호는 통과한다」.
4. **안정추구형 적합성 범위 답변이 «5종»으로 잘못 센다 (SH6 · PJ3 — 두 번 재현).** 재료는
   안내 가능 6종 · 불가 6종인데 생성문이 원장에 없는 수 «5» 를 써서 verify 게이트가 폐기했다.
   게이트는 맞게 동작했고 답은 원문 폴백으로 나갔다. 다른 성향(적극 11종 · 위험중립 8종 ·
   공격 12종)에서는 세는 것이 맞았다 — 안정추구형 재료의 목록 모양을 볼 자리.
   **고침(2026-09-07).** 원인은 `suitable` 도구가 제외 목록을 5건에서 자르던 상한
   (`BLOCKED_MAX`)이었다 — 재료가 «6종»이라 쓰고 5건만 보여주니 LLM 이 «5종»으로 셌다. 상한을
   없애 제외 상품을 전부 싣는다. 회귀: `tests.test_consult_agent::check_suitable_shape`
   「머리말의 수와 목록 줄 수가 같다」.
5. **콘텐츠 이름을 바꿔 쓰면 발송 화면 제안이 안 붙는다 (SE6 → SE7).** `act._propose_lms` 는
   답변이 콘텐츠 이름을 그대로 인용했는지로 «가리켰다»를 판정한다(`_mentions`). 답변이
   «ISA 만기자금, IRP로 이어가는 절세 이벤트»를 «ISA 만기자금 IRP 이전 절세 이벤트»로 줄여 쓰자
   제안이 빠졌고 승낙 턴이 공중에 떴다. 같은 질문이 다른 세 고객(HS7 · JM7 · PJ6)에서는 붙었다.
   **고침(2026-09-07).** 판정 기준에 링크를 더했다 — `outreach` 재료가 콘텐츠마다 `url` 을
   발송 목록에 함께 싣고, `act._mentions` 는 이름 대조 **또는** 그 링크 인용 중 하나면 «가리켰다»로
   본다. 링크는 원문 스팬이라 답변이 바꿔 쓸 수 없고 콘텐츠마다 다르다. 이름도 링크도 없는
   답변에는 지금처럼 안 붙는다. 회귀: `tests.test_consult_agent::check_outreach` 「이름을 바꿔
   써도 링크를 인용한 답변에는 그 콘텐츠의 제안이 붙는다」.
6. **고객 계산이 필요한 질문이 제도 일반론으로 간다 (DY4).** 「ISA 만기자금 IRP로 넣으면
   세액공제 받아?」에 계획이 `tax_credit` 대신 `fact` 만 불러, 이 고객의 잔여한도 0(현금 축
   추가 공제 없음)이 빠진 채 «최대 1,200만원까지 공제 대상»으로 답했다. 한지우 JW4(같은 질문에
   금액이 있음)는 `tax_credit` 로 갔다 — 금액이 없는 «받아?» 꼴이 계획에서 제도 질문으로 읽힌다.
7. **되묻기가 값 질문을 삼킨다 (JM2).** 「올해 얼마 넣었어? 세액공제 더 받을 수 있어?」에서
   앞 절(납입액 400만 · 잔여 500만)은 원장 값인데, 뒤 절이 `tax_credit` 를 부르며 총급여 구간
   되묻기로 턴이 끝나 값이 나가지 못했다. 되묻기 턴에도 확정된 값은 먼저 답할 수 있어야 한다.
8. **원장이 아는 것을 되묻는다 (SM6 · GY7 · SM4).** 「예금 만기 되면 또 예금 할래요」의
   화법에 «고객 성향이나 상황이 어떤 경우인가요?»(위험중립형 · 만기 D-19 는 열려 있는 고객의
   값이다), 이탈 위험 기준에 «어떤 세그먼트?», 디폴트옵션 등록 절차에 «어떤 경우?»(최초 입금 /
   만기 / 옵트인 — 이 고객은 만기 D-19 다). 갈래는 실재하지만 고객 화면이 열려 있으면 코드가
   가릴 수 있는 갈래다.
9. **픽스처 오염 (SE5).** `src/session_data/171203-4815062.json` 이 저장소에 커밋돼 있었는데
   내용은 9/3 의 `tests.debug` CLI 연습 세션 3개(`debug-…`)뿐이었다 — 김서연은 원장에 상담
   기록이 없어 파일 자체가 없는 것이 정상이다. 에이전트는 저장소를 맞게 읽어 «9/4 상담 기록이
   있다»고 답했다. 이 실측과 함께 그 파일을 지웠다(「실행」 ③).
10. **곁가지 값이 빠진다 (HS2 · SY2 · DY2 · MS7).** «얼마야»에 금액만, «얼마나 손실이야»에
    수익률만, «얼마나 됐어»에 요건 라벨만. 틀린 것은 없으나 재료에 있는 짝(비중 · 평가금액 ·
    원금 · 운용지시일)이 빠진다. 재료 요건은 서 있고(§3 「금액과 비중을 둘 다」), 작성 지시가
    «묻는 값 하나»로 좁혀 읽는 자리다.
11. **더미 금리가 논거 중심에 선다 (HS4).** 화법 카드(pitch.k03.020) 원문에 현금성자산 적용
    금리 2.42% 가 들어 있어 답변이 그것을 앞세운다. 화면에 더미 표시를 붙이지 않기로 했으므로
    (`DEMO_STATUS.md` §2) 시연에서는 이 질문을 «금액이 적어도 왜 굴려야 하나»로 좁혀 묻는다.

**게이트가 맞게 막은 것**: GY5(원장에 없는 날짜) · SH6/PJ3(원장에 없는 수). 폐기된 자리에
원문이 그대로 나가 «문체가 달라지는 자리»가 되는 것은 설계된 동작이다(기준서 §6).
