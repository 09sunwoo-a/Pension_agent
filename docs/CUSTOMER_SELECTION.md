# 부점 고객을 찾아 이어서 질문하기

조건 검색(`branch_search`)·관리 대상 추천(`branch_targets`) 결과는 번호가 있는 마크다운 표다.
표의 `목록 N`과 고객 번호를 서버가 내부 식별자에 연결한다. 이름·마스킹된 PIN 을 LLM 이 보고
고객 id 를 만들어 연결하지 않는다.
목록·중점관리 대상 여부와 관계없이 이름 질문은 **현재 직원 소속 부점 전체**에서 정확 일치 조회한다.
목록을 조회하기 전에도 `박지민 고객 자세히 알려줘`로 시작할 수 있다. 이름 조회 후보는 별도로 저장해
기존 표의 순번과 최근 목록을 바꾸지 않는다. 목록이나 번호를 명시하면 해당 표의 선택 범위를 따른다.

| 상황 | 질문 예시 | 동작·답변 예시 |
|---|---|---|
| 번호가 명확함 | 2번 고객 만기 상품은? | 2번 고객을 원장에서 확인하고 선택. “2번 박지민 고객 기준으로 확인했어요.” 뒤에 질문의 답변 |
| 이름이 유일함 | 박지민 고객 자세히 | 소속 부점 전체에서 이름이 정확히 일치하는 한 명을 선택. 이전 목록에 없어도 조회 |
| 이미 선택함 | 그 고객 세액공제는? | 선택한 고객을 유지하고 질문에 답변 |
| 동명이인 | 홍길동 고객 만기 상품은? | 부점 전체에서 동명이인을 확인. 별도 후보 번호·나이·등급으로 되묻고 원래 질문 보관. 기존 표에 한 명만 있어도 임의 확정하지 않음 |
| 동명이인 확인에 답함 | 7번 / 49세 고객 | 해당 후보 한 명으로 구분되는지 확인하고 원래 질문에 답변. 나이·등급이 겹치면 번호로 재확인 |
| 이름 일부만 말함 | 김 고객 자세히 | 성만 보고 선택하지 않고 후보의 목록 번호나 전체 이름을 요청 |
| 부점에 없는 이름 | 김없는 고객 만기는? | “현재 직원의 소속 부점 전체 고객에서 확인되지 않아요.” 다른 부점이나 비슷한 이름으로 대체하지 않음 |
| 이름과 번호가 다름 | 2번 고객 김현수 | “2번은 박지민 고객이에요. 말씀하신 이름과 달라 연결하지 않았어요.” |
| 번호가 범위를 벗어남 | 56명 목록에서 99번 고객 | 실제 목록 인원과 없는 번호를 알리고 재지정 요청 |
| 한 번에 여러 고객 지정 | 2번 고객과 3번 고객 | 현재 상세 상담은 한 고객씩 지원하므로 먼저 확인할 고객 요청 |
| 고객을 선택하지 않음 | 이 고객 만기 상품은? | “아직 고객이 선택되지 않았어요. 목록의 번호나 이름으로 지정해 주세요.” |
| 목록 자체가 없음 | 새 세션에서 2번 고객 | 번호로 선택할 목록이 없다고 안내. 전체 이름으로 바로 찾거나 조건 조회 가능 |
| 새 목록을 조회함 | 다른 조건으로 고객 보여줘 | 새 목록을 저장하고 기존 고객 선택 해제. 이후 번호는 새로 표시한 목록 기준 |
| 이전 목록을 지정함 | 이전 목록의 2번 고객 / 목록 1의 2번 고객 | 보관된 해당 목록의 2번으로 해석. 보관하지 않는 목록이면 재조회 요청 |
| 어느 이전 목록인지 모호함 | 목록 여러 개를 본 뒤 “아까 2번 고객” | “어느 목록인지 확인이 필요해요. 목록 번호와 고객 번호를 함께 말씀해 주세요.” |
| 목록을 다시 보고 싶음 | 목록 다시 보여줘 / 이전 목록 다시 보여줘 | 저장된 표를 같은 순번으로 다시 표시. 고객 선택은 해제 |
| 조회 결과가 0명임 | 새 조건 결과 0명 후 2번 고객 | 이전 목록으로 돌아가 선택하지 않음. 현재 목록에는 해당 번호가 없다고 안내 |
| 인원·합계만 조회함 | 이 고객군 몇 명이야? | 집계는 고객 명단을 새로 표시한 것이 아니므로 기존 목록·선택 유지 |
| 시간이 지났거나 날짜가 바뀜 | 어제 목록의 2번 고객 | 유효하지 않은 목록으로 안내하고 조건 재조회 요청 |
| 직원·부점·세션이 바뀜 | 다른 직원/세션에서 같은 번호 질문 | 이전 선택을 사용하지 않음. 현재 직원 부점의 고객을 다시 조회하도록 안내 |
| 원장 고객이 달라지거나 없어짐 | 조회 뒤 이름·나이 변경/행 삭제 | 다른 고객으로 대체하지 않고 목록 재조회 요청 |
| 상세 원장은 없음 | 중점관리 대상이 아닌 고객 자세히 | 부점 DB의 나이·등급·성향·잔액·수익률·공제 잔여한도·다음 만기일/금액을 표로 표시. 원장 출처를 제공하고 보유상품별 내역·상담이력 미연결을 안내 |
| 연결용 식별자 없는 조회 | 식별자 없이 조회된 명단의 2번 고객 | 번호를 이름으로 추정 연결하지 않고 재조회 요청. 전체 이름으로 새로 물으면 부점 전체를 정확 일치 조회 |
| PIN 으로만 지칭 | 171203-4****** 고객 | PIN 으로 추정하지 않고 목록 번호나 이름 요청 |
| 화면 고객과 대화 지정이 다름 | 화면은 A 고객인데 목록의 B 고객 지정 | 어느 고객인지 혼동하지 않도록 화면 선택 해제 후 재지정 요청 |
| 원장을 확인할 수 없음 | DB 장애 중 고객 선택 | 연결하지 않고 잠시 후 다시 시도하도록 안내 |
| 선택 해제 | 고객 선택 해제 | 선택을 지우고 목록은 유지 |

## 자연스럽게 이어가는 추천 질문

| 대화 단계 | 추천 예시 |
|---|---|
| 고객 목록을 표시함 | 목록의 실제 이름으로 `박지민 고객을 자세히 알려줘`, `김현수 고객을 자세히 알려줘` |
| 고객이 선택됨 | `박지민 고객의 만기 상품을 확인해줘`, `박지민 고객의 세액공제 잔여한도를 알려줘`, `박지민 고객의 보유상품과 수익률을 알려줘` |
| 동명이인 확인 중 | `49세 홍길동 고객으로 확인해줘` — 나이도 같으면 `49세 VIP 등급의 홍길동 고객으로 확인해줘`. 선택하면 원래 질문을 이어서 처리 |
| 어느 목록인지 확인 중 | `목록 1 다시 보여줘`, `목록 2 다시 보여줘` |
| 목록 만료·원장 변경 | 안전하게 재실행할 수 있는 원래 조건 질문 |

추천 질문은 최대 3개이며 억지로 채우지 않는다. 목록의 앞 10행 안에서 내부 식별자로 현재 원장 연결이
확인된 고객을 제안한다. 부점 DB 기본정보만 있는 고객도 해당 정보로 연결할 수 있다.
상세 원장이 있는 선택 고객에게는 실제 자료가 있는 항목만 제안하고 이미 물은 항목은 제외한다.
이름·나이·등급은 표시한 목록에서 가져온다. 같은 이름이면 나이, 나이도 같으면 등급을 덧붙인다.
구분 정보까지 같으면 이름으로 특정하는 추천은 생략하며 기존 번호 선택은 계속 지원한다. 이미 확정한 고객은
이름 표현만으로 구분할 수 없을 때 `이 고객`으로 이어간다. 추천 문장을 다시 해석하고 원장까지 확인한 뒤 표시한다.
이름 질문은 부점 전체에서 재확인하므로 표 밖의 동명이인을 무시하지 않는다.
전체 브리핑을 이미 보여줬으면 같은 수치를 다시 묻기보다 상담·적합성·상담이력으로 이어간다. 다른 고객을
선택하면 그 고객에게는 아직 묻지 않은 질문을 다시 제안할 수 있다.

고객을 확인하는 중에는 상담 질문을 섞지 않는다. 원장 장애·화면 고객 충돌·발송 확인 대기·LLM 장애에는
조회를 유도하는 추천을 표시하지 않는다. 만료 뒤의 조건 재조회는 의도적인 복구이므로 이전 질문을 다시
제안할 수 있다. 질문은 코드로 생성하며 추가 LLM 호출이 없다. 기존 `followups.items` 로 제공하고,
CLI 답변에는 기존 추천질문 블록으로 붙는다.

## 저장 범위와 확인

최근 목록 최대 3개를 직원·세션별 메모리 맥락에 보관한다. 2시간이 지나거나 날짜가 바뀌면
번호 연결을 다시 사용하지 않는다. 컨테이너 재시작·다른 워커 이동 시 맥락은 소멸하므로 먼저 재조회한다.
별도 이름 조회 후보에도 같은 직원·세션·부점 검증과 유효기간을 적용한다. 이름을 다시 지정하면 부점 전체를
새로 조회하며, 새 표를 표시하면 이름 조회 후보와 기존 선택도 해제한다. 전체 부점 명부를 세션에 저장하지 않는다.
`Turn.customer_context` 는 모델 프롬프트에 포함하지 않는다.

SQLite 목업은 부점과 원장 행 번호를 조합한 내부 키로 연결한다. 상세 원장이 있는 목업 고객은
생성 시 기록한 식별자 매핑으로 찾고, 이름으로 상세 고객을 조인하지 않는다. 실제 Sybase 고정 뷰는
아직 TODO 이며 실제 원장 전환 시 안정적인 고객 키와 상세 원장 연결이 필요하다. 전월말 조회 행은
오늘 원장에 잘못 연결되지 않도록 연결용 키를 비워 둔다.

검증: `cd src && python -m tests.test_customer_selection`. LLM 을 스텁으로 교체한 실제 HTTP 요청으로
목록 → 고객 선택 → 후속 질문 → 오류 안내 → 다른 세션 분리를 검사한다. 실 LLM 의 자연어 해석·운영
게이트웨이·Sybase 는 이 검사에 포함하지 않는다.
