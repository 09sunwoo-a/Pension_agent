# 모니터링 설계 — 검증·자동 처리·대시보드 (내부 검토용 초안)

| 항목 | 내용 |
|---|---|
| 문서 상태 | 내부 검토용 초안 |
| 범위 | 1단계(비대화형·배치). 2단계 대화형에서 추가되는 항목은 §7 |
| 기준치 | 이 문서의 기준치(%, 횟수)는 **초기 제안값**이다. 0단계 시연과 1단계 초기 운영 데이터로 확정한다 |
| 화면 시안 | `모니터링_대시보드.html` (예시 데이터) |

---

## 1. 설계 원칙

1. **고객에게 나가기 전에 모든 건을 검증한다.** 배치 구조라서 생성과 발송 사이에 시간이 있다.
2. **개별 건을 사람이 처리하는 보류 대기열을 두지 않는다.** 검증에 걸린 건은 재생성 → 대체 → 미발송 순서로 자동 처리한다.
3. **사람은 비율을 본다.** 개입 단위는 고객 한 명이 아니라 이슈 유형 하나다. 그래서 고객 수가 늘어도 관리 업무가 늘지 않는다.
4. **사람이 직접 확인하는 것은 배포 시점뿐이다.** 새 이슈 유형을 켜거나 프롬프트·모델을 바꿀 때 표본을 확인한다.
5. **검증은 LLM이 끌 수 없다.** 검증과 자동 처리는 코드에 있고, LLM 출력은 검증의 입력일 뿐이다.

## 2. 건별 자동 검증과 자동 처리 (모니터링 층 ①)

### 2.1 처리 방식

| 처리 | 내용 | 집계 지표 |
|---|---|---|
| 재생성 | 같은 재료로 LLM에게 한 번 더 쓰게 한다 (1회) | 재생성률 (보조 지표) |
| 대체 | LLM 판단·문장 대신 안전한 기본값: 모델포트폴리오 비중 / 계산값만 넣은 정형 문구 / 전문가 상담 연결 카드 | **대체율** |
| 미발송 | 이번 배치에서 보내지 않고 다음 배치에서 다시 계산 | **미발송율** |

## 3. 배포 시 표본 검수 (모니터링 층 ②)

상시 업무가 아니라 배포 절차의 한 단계다.

| 언제 | 무엇을 | 누가 | 통과 기준 (초기 제안값) |
|---|---|---|---|
| 새 이슈 유형을 처음 켤 때 | 해당 유형 생성 결과 표본 100건 | PB 1인 + 우리 팀 기획자 | 반려 3건 이하 |
| 프롬프트·LLM 모델을 바꿀 때 | 전 유형에서 표본 50건 + 정답 세트 회귀 시험(층 ③) 결과 | 우리 팀 개발자·기획자 | 반려 2건 이하, 회귀 시험 통과 |
| 판단 기준(하우스뷰 등)이 바뀔 때 | 검수 없음. 기준 변경은 사유 8로 자동 처리 | — | — |

반려 기준: 수치는 맞지만 PB가 보기에 고객에게 맞지 않는 제안, 설명이 오해를 부를 수 있는 문장.

표본 검수를 없애면 "처음 켠 유형이 전부 틀려도 대체율이 오를 때까지 모른다"는 위험이 남는다. 대체율은 코드 점검에 걸린 것만 세므로, 점검을 통과하지만 부적절한 제안은 대체율에 나타나지 않는다.

## 4. 정답 세트 회귀 시험 (모니터링 층 ③)

| 항목 | 내용 |
|---|---|
| 정답 세트 | PB가 검토해 "이 고객에게는 이런 제안이 맞다"고 확인한 사례 모음. 초기 이슈 유형별 20건 |
| 비교 방법 | 코드 계산값은 정확히 일치해야 함. LLM 판단 값은 PB가 정한 허용 구간 안이어야 함. 우선순위 1위 이슈가 같아야 함 |
| 실행 시점 | 프롬프트·모델·판단 기준 변환 로직 변경 시 자동 |
| 실패 시 | 배포 중지 |
| 파일럿 근거 | 파일럿은 LLM 키 없이 도는 시험 묶음과 평가용 정답 세트(`strategy_agent/data/outreach_golden.json`, LLM 입력에 넣지 않음)를 두고 있다. 같은 방식을 확장한다 |

## 5. 운영 대시보드 (모니터링 층 ④)

### 5.1 핵심 지표 3개 — 사람이 매일 보는 것

| 지표 | 산식 | 경고 (초기 제안값) | 자동 조치 (초기 제안값) | 담당 |
|---|---|---|---|---|
| **대체율** | (사유 1~6으로 대체된 건) ÷ (생성 건) — 이슈 유형별 | 이슈 유형별 15% 초과 또는 전일 대비 2배 | 30% 초과 시 해당 이슈 유형 **자동 일시 중지** | 우리 팀 |
| **미발송율** | (사유 7~10으로 미발송된 건) ÷ (생성 건) | 전체 10% 초과 | 없음 (데이터 연동·기준 갱신 문제 확인) | 우리 팀 |
| **실행률** | (발송 후 30일 내 제안과 일치하는 거래가 확인된 건) ÷ (발송 건) | 이슈 유형별 4주 연속 하락 | 없음 | 우리 팀 + WM플랫폼 팀 |

대체율 경고가 뜨면: 해당 이슈 유형의 사유 분포를 본다 → 사유 1~3이 많으면 프롬프트 문제, 4~5가 많으면 LLM 판단 또는 기준선 문제, 6이 많으면 판단 기준 자료 부족 → 원인 수정 후 표본 검수(층 ②)를 거쳐 다시 켠다.

### 5.2 보조 지표 — 원인을 찾을 때 보는 것

| 지표 | 내용 | 이 지표로 알 수 있는 것 |
|---|---|---|
| 판단 등급 비중 | 발송된 값 중 [기준] / [LLM 판단] / [대체] 비중 | 엔진이 행내 기준에 얼마나 기대고, LLM 판단을 얼마나 쓰는지 |
| 대체 사유 분포 | 사유 1~6별 건수 | 대체가 왜 일어나는지 |
| 기준선 대비 LLM 판단 분포 | 고객군별 LLM이 정한 주식 비중의 분포와 기준선 구간 | LLM 판단이 한쪽으로 치우치는지, 기준선 경계에 몰리는지 |
| 판단 흔들림 비율 | 고객군별 사유 5 발생 비율 | 판단에 필요한 데이터가 빠진 고객군 |
| 재생성률 | 재생성으로 통과한 비율 | 재생성이 실제로 효과가 있는지 |
| 발송 퍼널 | 생성 → 발송 → 열람 → 카드 클릭 → 실행 | 어느 단계에서 이탈하는지 |
| 기준 없음 영역 | 사유 6 건수의 영역별 분포 | 다음에 어떤 영역의 행내 기준을 먼저 확보할지 |
| 운영 | 배치 소요 시간, LLM 호출 수·비용, 오류 | 규모가 커질 때의 비용과 안정성 |

### 5.3 화면 구성 (`모니터링_대시보드.html`)

| 영역 | 내용 |
|---|---|
| 상단 | 배치 실행 일시, 기준 버전(하우스뷰·금리·비교집단), 경고 목록 |
| 핵심 지표 | 생성 건수, 대체율, 미발송율, 실행률 (전일 대비 변화) |
| 이슈 유형별 표 | 유형별 생성·대체율·미발송율·실행률, 상태(정상/경고/중지), 마지막 배포·표본 검수 결과 |
| 추이 | 최근 14일 대체율·미발송율 |
| 판단 등급 | 이슈 유형별 [기준]/[LLM 판단]/[대체] 비중 |
| 대체 사유 | 사유 1~6 분포 |
| 판단 분포 | 고객군별 LLM 판단(주식 비중) 분포와 기준선 구간 |
| 발송 퍼널 | 생성 → 실행 |

### 5.4 대시보드에서 할 수 있는 조치

| 조치 | 권한 | 기록 |
|---|---|---|
| 이슈 유형 일시 중지 / 재개 | 우리 팀 (재개는 표본 검수 통과 후) | 조치자·사유·일시 |
| 특정 고객군 일시 중지 | 우리 팀 | 같음 |
| 건별 기록(트레이스) 열람 | 우리 팀, 민원 대응 담당 | 열람 기록 |

일시 중지된 이슈 유형의 고객에게는 해당 이슈 카드가 나가지 않는다. 다른 이슈 카드는 정상 발송된다.

## 6. 건별 기록 (트레이스)

| 항목 | 내용 |
|---|---|
| 목적 | 고객 민원이나 이상 제안이 있을 때, 한 건의 제안이 어떤 입력값·기준 버전·계산·LLM 출력·검증 결과에서 나왔는지 재현 |
| 기록 단위 | 고객 1명 × 배치 1회 |
| 기록 내용 | 입력 데이터 스냅샷, 감지 이슈, 계산 결과(원장), LLM 호출별 입력·출력, 판단 흔들림 3회 결과, 검증 결과와 처리 사유, 최종 카드, 노출 직전 확인 결과 |
| 구현 | 파일럿의 Langfuse 트레이스(`pension_agent/observability/`)를 확장 |
| 필수 조치 | 파일럿 기본 설정은 프롬프트 전문을 외부 클라우드로 보낸다(`docs/PRODUCTION_RISKS.md` §9). **행내 자체 설치로 전환**하고, 고객명·계좌번호 등 식별 항목의 마스킹 규칙을 정한다. 망분리 환경에서는 외부로 나갈 수 없으므로 법적 제한과 별개로 필요한 조치다 |
| 보존 | 발송 건은 1년(초기 제안값), 미발송 건은 90일 |

## 7. 2단계(대화형)에서 추가되는 것

| 항목 | 내용 |
|---|---|
| 실시간 검증 | 대화형 답변은 생성 즉시 고객이 보므로 발송 전 시간이 없다. 건별 자동 검증(사유 1~6)은 답변 직전에 동기로 수행하고, 대체 시 정형 답변을 낸다 |
| 고객 입력 해석 정확도 | 해석값 확인 화면에서 고객이 [아니에요]를 누른 비율 → LLM 해석 품질 지표 |
| 질문 효율 | 고객에게 물은 질문 수 대비 계획이 실제로 바뀐 비율 → 불필요한 질문이 많은지 |
| 고객 기준 저장 | 저장된 고객 기준 수, 기준이 적용되어 제외된 대안 수 |
