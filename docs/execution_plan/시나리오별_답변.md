# 시나리오별 답변 — 엔진이 어떤 상황에서 어떤 결과를 내는가 (설계 예시)

| 항목 | 내용 |
|---|---|
| 문서 상태 | 내부 검토용 초안 |
| 성격 | **설계 예시다. 엔진의 실제 출력이 아니다.** 자산관리 전반 엔진은 아직 없으므로, "엔진이 이렇게 동작하도록 설계한다"를 고객 사례로 보인 것이다 |
| 수치 | 금액·금리·비율은 설명용 예시값이다. 다만 한 시나리오 안의 수치는 서로 맞게 계산했다 (예: 이자 차이 73만 원 = 2,000만 원 × 6.2% − 2,000만 원 × 3.0% × (1 − 15.4%)) |
| 상품명 | 실제 상품명 대신 `[상품 후보 A]` 형태로 적는다 |
| 함께 보는 문서 | `실행기획안.md` §5 (엔진 작동 방식), `모니터링_설계.md` §2 (자동 처리 사유 10가지) |

## S1. 예금 만기 — 여러 이슈를 하나의 자금 계획으로

**배치 실행**: 2026-10-21 02:00

### 입력 데이터 (행내 데이터만 사용)

| 항목 | 값 | 구분 |
|---|---|---|
| 나이·투자성향 | 45세, 적극투자형 (2026-03 평가) | 확정 |
| 급여 입금 | 월 520만 원 | 확정 |
| 월 지출(카드·자동이체 평균 6개월) | 320만 원 | 확정 |
| 정기예금 | 1억 원, **2026-10-20 만기 → 입출금 계좌에 입금됨** | 확정 |
| 입출금 계좌 | 800만 원 (만기금 제외) | 확정 |
| 펀드 | 3,000만 원 (주식 85% / 채권 15%) | 확정 |
| ISA | 평가액 3,400만 원, **2026-11-05 만기** | 확정 |
| 신용대출 | 2,000만 원, 연 6.2% | 확정 |
| 전세자금대출 | 1억 5천만 원, **2028-03-15 만기** | 확정 |
| 총급여 | 7,800만 원 (급여 입금액에서 역산) | **추정** |
| 자녀·학자금 | 행내 데이터 없음 | 없음 → 계획에 반영하지 않고 "미반영" 표시 |

### 감지된 이슈 (코드)

| 이슈 | 감지 조건 |
|---|---|
| 만기 자금 1억 원 | 정기예금 만기 해지금 입금 |
| 고금리 부채 | 신용대출 금리(6.2%) − 재예치 금리(3.0%) ≥ 2%p |
| ISA 만기 | 만기 30일 이내 |
| 전세대출 만기 | 만기 24개월 이내 |
| 투자자산 주식 쏠림 | 펀드 내 주식 비중이 모델포트폴리오(적극투자형 60%) + 15%p 초과 |

### 상황 구조화 (LLM)

5개 이슈를 따로 안내하지 않고 하나의 문제로 묶음: **"만기 자금 1억 원과 ISA 만기 자금을, 고금리 부채 정리·17개월 뒤 전세 만기 대비·투자 비중 조정에 어떻게 나눌 것인가"**

### 계산 (코드)

| 계산 | 결과 | 등급 |
|---|---|---|
| 신용대출 2,000만 원 상환 시 연간 이자 절감 | 124만 원 | [기준] |
| 같은 금액을 연 3.0% 예금에 둘 때 세후 이자 | 50.76만 원 (이자소득세 15.4%) | [기준] |
| 상환의 순효과 | **연 73만 원** | [기준] |
| ISA 만기 자금 연금계좌 이전 시 추가 세액공제 | 이전액의 10%, 최대 300만 원 → 3,000만 원 이전 시 공제대상 300만 원 → **39.6만 원** (공제율 13.2%) | [기준] |
| 위 계산의 민감도 | 총급여가 5,500만 원 이하라면 공제율 16.5% → 49.5만 원 | 추정값 표시 |
| 연금계좌 이전 자금의 제약 | 55세 이전 인출 시 기타소득세 부과 → 전세·학자금 용도로 쓸 수 없는 돈으로 분류 | [기준] |
| 상품 후보 | 하우스뷰 비중확대 자산군 중 적극투자형 적합성 통과 상품: [상품 후보 A] 글로벌 채권형, [상품 후보 B] 국내외 주식혼합형 | [기준] |

### 판단 (LLM) 과 자동 점검

| 판단 | LLM 결정 | 이유 기록 | 기준선 | 흔들림(3회) | 등급 |
|---|---|---|---|---|---|
| 신용대출 상환 금액 | 2,000만 원 전액 | 순효과 연 73만 원, 상환 수수료 없음 | — (계산으로 결정되는 판단) | 2,000 / 2,000 / 2,000 | [LLM 판단] |
| 전세 만기 대비 예치 | **4,000만 원**, 2028년 2월 만기 정기예금 | 전세대출 만기까지 17개월, 보증금 증액 가능성 대비 | 이후 유동성 비중 34% / 비교집단(45~49세, 전세대출 만기 24개월 이내) 15~45% → 안 | 4,000 / 4,000 / 3,500 (차이 500만 원, 허용) | [LLM 판단] |
| 투자자산 내 주식 비중 | **65%** (현재 85%) | 투자기간 5년 이상, 단기 자금은 별도 확보됨 | 비교집단(45~49세 적극투자형) 40~80% / 모델포트폴리오 60% ± 15%p → 안 | 60 / 65 / 65 (차이 5%p, 허용) | [LLM 판단] |
| ISA 만기 자금 | 3,000만 원 연금계좌 이전, 400만 원 입출금 계좌 | 추가 세액공제 한도를 채우는 최소 금액만 이전, 나머지는 유동성 | — | 같음 | [LLM 판단] |
| 우선순위 | ① 신용대출 상환 ② ISA 이전(만기 후 60일 기한) ③ 전세 대비 예치 ④ 투자 | 확실한 이익·기한 순 | — | 같음 | [LLM 판단] |

배분 결과: 1억 원 = 신용대출 상환 2,000만 + 전세 대비 예금 4,000만 + 투자 4,000만([상품 후보 A] 2,000만, [상품 후보 B] 2,000만) → 투자자산 합계 7,000만 원 중 주식 4,550만 원(65%)

### 생성된 카드 (LLM 문장)

> **만기 예금 1억 원, 이렇게 나눠 보시면 어떨까요**
>
> 1. **신용대출 2,000만 원 먼저 갚기** — 대출이자(연 6.2%)가 예금이자(연 3.0%)보다 높아, 갚으시면 연 73만 원을 아낄 수 있어요.
> 2. **ISA 만기 자금 중 3,000만 원은 연금계좌로** — 11월 5일 ISA 만기 후 60일 안에 옮기시면 세액공제를 최대 39.6만 원 더 받을 수 있어요. 이 돈은 55세 전에 찾으면 세금이 붙으니, 남은 400만 원은 입출금 계좌에 두세요.
> 3. **4,000만 원은 2028년 2월 만기 예금에** — 2028년 3월 전세대출 만기 때 보증금이 오를 경우에 대비한 금액이에요.
> 4. **나머지 4,000만 원은 투자** — 지금 펀드는 주식이 85%라 한쪽에 치우쳐 있어요. [상품 후보 A]·[상품 후보 B]에 2,000만 원씩 나누면 투자자산 중 주식이 65%가 돼요.
>
> 참고: 자녀 학자금 등 은행이 알 수 없는 계획은 반영하지 않았어요.

**push 문구**: "예금 1억 원이 만기됐어요. 대출 상환·세액공제·투자까지 한 번에 정리해 드렸어요."

## S2. 3개월 뒤 큰 출금 — 영향받는 제안만 재계산

**배치 실행**: 2027-01-15 02:00 (S1 고객)

### 무엇이 바뀌었나 (거래 데이터로 확인)

| 항목 | 값 |
|---|---|
| 실행된 제안 | ① 신용대출 상환 ✔ ② ISA 3,000만 원 연금계좌 이전 ✔ ③ 2028년 2월 만기 예금 4,000만 원 ✔ |
| 실행되지 않은 제안 | ④ 투자 4,000만 원 → 입출금 계좌에 그대로 있음 |
| 새 이벤트 | 2027-01-14 이체 1,500만 원 (수취인: OO병원) |
| 입출금 계좌 잔액 | 5,200만 원 → **3,700만 원** |

### 영향 판정 (코드)

계획 v1의 제안 중 "입출금 계좌 잔액"에 기댄 제안은 ④ 투자뿐이다. ①~③은 이미 실행되어 재계산하지 않는다.

### 계산과 판단

| 항목 | 값 | 등급 |
|---|---|---|
| 월 지출 | 320만 원 | [기준] |
| 비상자금 개월 수 | **4개월** (가족 의료비 지출이 생겨 최소 기준보다 넉넉히) | [LLM 판단] — 비교집단 2~8개월 안, 3회 4 / 4 / 3 |
| 비상자금 | 1,280만 원 | 계산 |
| 투자 가능 금액 | 3,700만 − 1,280만 = 2,420만 → **2,400만 원** (100만 원 단위) | 계산 |
| 투자자산 내 주식 비중 | 65% 유지 → 신규 2,400만 원 중 주식 960만 원 / 채권 1,440만 원 | [LLM 판단] (v1과 같음) |

### 생성된 카드

> **투자 계획을 조정했어요**
>
> 1월 14일 1,500만 원이 나가서 입출금 계좌 잔액이 3,700만 원이 됐어요. 생활비 4개월분(1,280만 원)은 그대로 두시고, 투자 금액은 4,000만 원에서 **2,400만 원**으로 줄이는 것을 권해요.
>
> 2028년 2월 만기 예금 4,000만 원(전세 대비)은 그대로 두시면 돼요.
>
> 계획이 바뀐 이유: 입출금 계좌 잔액 5,200만 원 → 3,700만 원

### 검증·저장

- 검증 통과. 계획 v2 저장, v1 대비 변경 사유 기록.
- 의료비로 판단한 근거(수취인명)는 카드 문장에 쓰지 않는다. 문장에는 금액과 날짜만 쓴다.

## S3. 문장에 계산 결과에 없는 금액

S1과 같은 고객을 다른 날 배치로 처리했다고 가정한다.

### 처리 기록

| 순서 | 내용 | 결과 |
|---|---|---|
| 1차 생성 | "신용대출을 갚으시면 연 **80만 원** 이상 이자를 아낄 수 있어요" | 검증 실패 — 80만 원은 계산 결과에 없음 (계산값 73만 원) |
| 재생성 | "연 **약 75만 원**의 이자를 아낄 수 있어요" | 검증 실패 — 75만 원도 계산 결과에 없음 |
| 대체 | 해당 항목만 정형 문구로 교체: "신용대출 2,000만 원 상환 시 연간 이자 차이(세후 예금이자 대비): **73만 원**" | 통과 → 발송 |

### 기록되는 것

- 대체 사유 코드: `수치_원장밖`
- 이슈 유형 "고금리 부채 상환" 의 당일 대체 건수 +1 → 대시보드 대체율에 반영
- 카드의 나머지 항목(ISA, 전세, 투자)은 LLM 문장 그대로 유지

### 설계 메모

- 반올림은 코드가 허용 표기를 함께 만든다(73.24만 원 → "73만 원"). LLM이 임의로 반올림한 값("약 75만 원")은 통과하지 못한다.
- 같은 이슈 유형에서 이 사유가 늘어나면 프롬프트 문제로 보고 개발자가 확인한다(개별 건이 아니라 비율로 본다).

### 판단과 점검

| 항목 | 내용 |

| LLM 판단 | 금융자산 중 주식형 비중 **55%** |
| LLM 이유 | "장기적으로 기대수익률을 높이기 위해" |
| 기준선 | 비교집단(60~64세 안정형) 0~18% / 모델포트폴리오(안정형) 주식 10% ± 10%p |
| 이탈 여부 | 두 기준선 모두 벗어남 |
| 이탈 사유 확인 | LLM이 지정한 이유가 고객 데이터의 특정 항목(미래 자금 이벤트, 부채, 투자기간 등)이 아님 → **사유 불인정** |
| 처리 | **[대체]** 모델포트폴리오(안정형) 비중 적용: 주식 10% |

### 생성된 카드 (대체 후)

> **만기 예금 1억 2천만 원 운용 안내**
>
> 고객님 투자성향(안정형)의 기본 배분은 예금·채권 90%, 주식 10%예요. 만기 자금도 이 비율에 맞춰 나눠 보시는 것을 권해요.

### 설계 메모

- 상품 단위로는 적합성 필터가 안정형 고객에게 고위험 상품을 거르지만, **비중 단위의 판단**(위험 상품을 몇 %나 담을지)은 적합성 필터만으로 잡히지 않는다. 기준선 점검이 이 부분을 맡는다.
- 이탈 사유로 인정되는 예: "18개월 뒤 대출 만기(데이터 항목: 주택담보대출 만기일)에 대비해 예금 비중을 높임". 고객 데이터 항목을 지정하고 그 항목이 실재해야 한다.

## S5. 같은 고객에 대한 LLM 판단이 흔들림

### 입력과 판단

| 항목 | 값 |
|---|---|
| 고객 | 52세, 위험중립형, 투자자산 5,000만 원 |
| 이슈 | 투자자산 주식 쏠림 |
| LLM 판단 3회 (투자자산 내 주식 비중) | 30% / 55% / 40% |
| 최대 차이 | 25%p > 허용폭 15%p |
| 처리 | **[대체]** 모델포트폴리오(위험중립형) 주식 40% 적용 |

### 설계 메모

- 세 값이 모두 기준선 안에 있어도, 같은 입력에 이렇게 다른 답이 나온다면 LLM이 이 고객에 대해 근거 있는 판단을 하지 못하고 있다는 뜻이다. 매일 배치를 돌리면 고객이 날마다 다른 비중을 받게 된다(허점 A1).
- 대시보드에서 고객군별 흔들림 비율을 본다. 특정 고객군에 몰리면 그 고객군에서 판단에 필요한 데이터가 빠져 있을 가능성이 높다.

## S6. 행내 기준이 없는 영역 — 재건축

### 입력

| 항목 | 값 |
|---|---|
| 고객 데이터 | 주택담보대출 담보 주택이 정비사업(재건축) 구역, 이주비 대출 상담 이력 있음 |
| 이슈 | 정기예금 8,000만 원 만기 |
| 행내 데이터에 없는 것 | 분담금 금액, 이주 시점, 입주 시점 |

### 처리

| 판단 | 처리 |
|---|---|
| 만기 자금의 운용 기간 | 이주 시점을 모르므로 결정하지 않음 → 짧은 만기(6개월) 기본값 **[대체]** |
| 분담금 대비 자금 규모 | 행내 기준·데이터 없음, 추정하지 않음 → **전문가 상담 연결 [대체]** |
| 입주권 관련 세금 | 개별 사실관계에 따라 달라짐 → **전문가 상담 연결 [대체]** |

### 생성된 카드

> **재건축 일정에 맞춘 자금 계획, 전문가와 함께 세워 보세요**
>
> 만기 예금 8,000만 원은 이주·분담금 일정이 정해질 때까지 6개월 만기로 짧게 두시는 것을 권해요. 분담금 준비와 관련 세금은 세무·부동산 전문가 상담에서 고객님 일정에 맞춰 안내받으실 수 있어요. [상담 예약]

### 설계 메모

- 2단계에서는 고객이 분담금 통지 금액·이주 시점을 입력하면 확정값으로 현금흐름을 계산할 수 있다(`실행기획안.md` 부록).

## S9. (2단계) 고객이 실제 증액 금액을 알려 줌

**시점**: 2027-06-10, 대화형

### 대화

| 주체 | 내용 |
|---|---|
| 고객 | "집주인이 내년 3월에 보증금 3천만 원 올려달래요." |
| LLM 해석 | 전세 보증금 증액 3,000만 원 / 시점 2028-03 / 구분: 고객 진술(확정 통보) |
| 화면 확인 | "이렇게 이해했어요: 2028년 3월 전세 보증금 **3,000만 원** 증액(집주인 통보). 맞나요?" → 고객 [맞아요] |
| 재계산 (코드) | 전세 대비 예금 4,000만 원 − 필요 3,000만 원 = 여유 1,000만 원 |
| 대안 (LLM 설계, 코드 계산) | A. 2028년 2월 만기 예금을 지금 1,000만 원 일부 해지해 투자 → 중도해지 이자 손실 계산값 표시 / B. 만기까지 유지하고 2028년 2월에 1,000만 원 운용 결정 → 손실 없음 |
| 목표 선택 (고객) | 두 안의 계산 결과를 보여 줌 → 고객이 **B** 선택 |
| 저장 | 진술 값 "증액 3,000만 원" (유효: 2028-03까지) / 고객 기준 "만기 전에는 묶인 예금을 깨지 않는다" |

### 이후 배치에 미치는 영향

- 이후 배치에서 예금 중도해지를 포함하는 대안은 고객 기준에 따라 제외되고, 카드에 "고객님이 정하신 기준에 따라 만기까지 유지하는 안으로 안내해요"라고 표시된다.
- 이 장면이 1단계에는 없는 것: 고객만 아는 정보(증액 금액)를 받는 수단, 해석값 확인, 목표 선택 저장.
