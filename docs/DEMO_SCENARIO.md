# 중간 시연 대본 — 대화형 에이전트

시연에서 **무엇을 어떤 순서로 물을지**와, 각 질문이 무엇을 보여주는지. 실행은
`cd src && python -m tests.debug.reps --demo` 로 그대로 리허설할 수 있다.

> 이 문서는 손으로 쓴다(생성물이 아니다). 무엇이 더미인지는 `DEMO_STATUS.md` 가 갖고 있고,
> 에이전트가 **무엇을 해야 하는가**는 `src/pension_agent/consult_agent/CLAUDE.md` 가 기준이다.
> 여기는 그중 **보여줄 것만** 골라 순서를 정한 자리다.

## 남길 메시지 셋

대본 전체가 이 셋을 향한다. 장면마다 어느 것을 심는지 표에 적어 뒀다.

| | 메시지 | 왜 이게 중요한가 |
|---|---|---|
| **A** | **근거가 있다** | 답이 행원들이 정리해둔 행내 문서에서 나오고, 값마다 출처·기준시점·신뢰 등급이 붙는다 |
| **B** | **스스로 계획한다** | 한 질문에 필요한 재료를 알아서 여러 개 모은다. 질문 유형별 버튼을 만들어 둔 것이 아니다 |
| **C** | **선을 안다** | 없으면 없다고 하고, 하면 안 되는 것을 먼저 말하고, 되돌릴 수 없는 행위는 직원에게 넘긴다 |

C 를 빼면 A·B 가 위험해 보인다. **셋을 같이 보여주는 것이 이 대본의 핵심**이고, 그래서
「모른다고 답하는 장면」(T12)이 잘라내면 안 되는 필수 장면에 들어 있다.

## 흐름 — 행내 문서의 영업 시점 축을 그대로 탄다

`07_에이전트_기능정의/01` 이 **① 영업 전 · ② 영업 중 · ③ 영업 후**로 나눠 놓았다.
청중이 자기 문서의 구조로 보게 되므로 그 축을 그대로 쓴다.

```
  0. 기본기        →  ① 상담 전        →  ② 상담 중        →  경계
  (고객 없이)         (송도윤 열기)        (같은 고객)          (믿을 이유)
  T1 T2 T3            T4 T5 T6            T7 T8 T9 T10 T11     T12 T13
                                          (T11b 발송 화면)
```

시연 고객은 **송도윤 (188406-7352194)** — 72세 · 위험중립형 · VIP · 적립금 5.2억.
고른 이유는 한 화면에 문제가 셋 겹쳐 있어서다: **방치 현금성자산 54%(2.8억)** ·
**ISA 만기 임박(1.2억 · 당행)** · **판매중단펀드 보유**, 그리고 **322일째(약 10개월) 미접촉**.
게다가 10개월 전 상담 기록에 「현금성자산은 단계적으로 재투자하고 싶다」는 본인 의사가
남아 있다 — T5 가 그 기록을 꺼내면서 오늘의 제안에 명분이 선다.

> **고객 화면을 열면 추천 질문 칩이 먼저 뜬다**(`consult_agent/suggest.py`). 칩은 두
> 갈래다 — 상담 기록 칩은 기록이 **있는 고객에만** 뜨고(송도윤은 「지난 상담(10/6 ·
> 322일 전)에서 무슨 얘기 했지?」), 안내 콘텐츠 칩(「안내할 만한 세미나·이벤트 N건 있어」)은
> 그 고객 상태에 걸린 콘텐츠가 열려 있으면 뜬다. 기록이 없는 김현수는 콘텐츠 칩만 뜨고
> 상담 기록 칩은 없다. **고객마다 다르게 뜨는 것 자체가 장면**이므로 T5 는 타이핑하지
> 말고 칩을 누르는 편이 낫다. 문구는 LLM 이 아니라 코드가 조립한다(날짜·경과일·건수는
> 계산값이라 지어낼 자리가 없다).

## 리허설 체크 — 들어가기 전에 확인할 것

`--debug` 를 붙이면 턴마다 이런 로그가 답변 아래 붙는다 — **시연에서 띄울 것은 이것**이다.
노드·게이트 트리를 그리는 전체 트레이스는 진단 도구라 청중에게 보여줄 것이 아니다.

```
   ┌ 무엇을 찾아봤나
   │ 1. fact «세액공제 한도»
   │      → fact.k04.f2  세액공제 — 한도 900만원 · 5,500만원 이하 16.5% / 초과 13.2%
   └ 위 재료만 보고 LLM 이 204자 작성 · 근거와 대조 통과
```

「지어낸 게 아니라 이 자료를 보고 썼다」가 한 눈에 보이는 것이 전부다. T9 에서 이 블록에
도구가 셋 찍히는 것이 대본에서 «에이전틱»을 눈으로 보여주는 유일한 자리다.

```bash
cd src
python -m tests.test_consult_agent      # 전부 통과하는지 (LLM 키 불필요)
python -m tests.debug.reps --demo        # 대본 전체를 실 LLM 으로
python -m tests.debug.reps --demo --debug   # + 「무엇을 찾아봤나 → LLM 이 썼다」 로그
```

- **T9 가 도구를 정말 여러 개 부르는가** — 여기가 대본에서 유일하게 «에이전틱함»을 눈으로
  보여주는 장면이다. 하나만 부르면 질문을 더 복합적으로 고쳐야 한다.
- **T9 가 면제 카드(F53)를 모순 없이 꺼내는가** — 송도윤은 퇴직금 5천만원 이상이라
  «비대면 전환 시 수수료 면제»가 증권사 무료 반론의 최우선 카드다(F50 표·F53). 주의할
  갈래: 화법 원문에 「퇴직금 5천만원 이상이면 면제」라는 문장이 있는데(pitch.k03.001),
  이 고객의 T8b 답은 **대면 0.38%** 다 — 답변이 «비대면 계좌 조건»을 빼먹고 면제라고만
  하면 앞 턴과 모순으로 들리고, 그건 오안내다. 「전환하면 면제」로 잇는지 본다.
- **T10 이 `suitable` 을 부르는가** — `lineup` 만 돌다 끝나면 「제외된 상품과 사유」가
  안 나온다. 그게 이 장면의 전부다.
- **T3 에서 연계 제안이 붙는가** — 안 붙으면 T3b 가 공중에 뜬다.
- **T11 답변이 콘텐츠 이름을 그대로 부르는가** — 발송 제안(`act._propose_lms`)은 답변이
  이벤트·세미나 **이름을 인용했을 때만** 붙는다. 후보를 늘어놓기만 하거나 이름을 줄여
  부르면 «열까요?»가 안 붙고 T11b 가 공중에 뜬다. 붙지 않으면 「그 세미나 문구로 보내줄
  준비 해줘」로 한 턴 더 가지 말고, 리허설에서 질문을 「…뭐가 좋을까? 이름이랑 일정도
  알려줘」로 고친다. T11b 는 `[75-08-110]` 딥링크와 «화면이 열리면 이 문구를 넣어 주세요»
  가 함께 나오면 된다.
- **T11 의 세미나는 날짜로 바뀐다.** 세미나는 하루짜리라 지난 것은 후보에서 빠진다 —
  8/24 고정 리허설에서 송도윤에게 뜨는 것은 「디폴트옵션 점검 세미나(9/10)」이고, 시연일이
  9/10 을 지나면 다른 세미나로 바뀌며 칩의 «3건»도 달라진다. 콘텐츠 이름을 대본에 외워 두지
  말고, 고정하고 싶으면 `PENSION_TODAY` 를 건다(잔여일수 항목과 같은 처리).
- **답변 끝의 추천질문이 말이 되는가** — 재료가 있는 것만 띄우게 돼 있다. 시연에서
  다음 질문을 그 칩으로 이어가면 «대화가 굴러간다»가 그대로 보인다.
- **질문과 답 사이에 진행 줄(「⋯ 자료를 찾고 있어요」)이 흐르는가** — 대기 UX 이면서,
  계획 루프의 단계(이해 → 도구 선택 → 조회 → 확인 → 작성 → 검증)가 화면에 그대로 나오는
  실황이다. 발표에서 "지금 뜨는 단계가 실제로 도는 단계입니다" 한 마디를 얹을 자리다.
  문구는 전부 코드가 정한다(`progress.py`) — LLM 이 지어내는 줄이 아니다.
- **T12 가 정말 «없다»고 하는가** — 여기서 그럴듯한 문장을 지어내면 대본의 메시지 C 가
  통째로 무너진다. 가장 확인이 중요한 한 턴이다. 첫 리허설에서는 **당행 수수료표를 펴
  놓고 끝났다** — 틀린 문장은 하나도 없는데 물은 것에는 답하지 않은 답변이다. 생성 지시
  9번(「핵심 대상이 재료에 없으면 그것이 결론」)을 그래서 넣었다. 첫 문장이 「타행 수수료
  자료는 없어요」로 시작하는지만 보면 된다.
- **T13 이 12종을 12종이라 말하는가** — 정민석은 상한이 최고 등급이라 카탈로그 전부가
  범위 안이다. 「11종」이 나오면 LLM 이 하나를 골라 뺀 것이고, 그건 직원이 그 상품을
  «안내 불가»로 읽는다는 뜻이다. 첫 두 리허설에서 연속으로 그랬다.
- **화면에 「적합성 게이트」가 나오지 않는가** — 개발 용어다. 재료에서 걷어냈으므로
  답변은 「안내 범위를 벗어나요」로 말한다.
- **폐기된 턴이 몇 개인가** — `--debug` 가 「검증에서 걸림(…)」과 그 사유를 함께 찍는다.
  폐기되면 화면에 카드 원문이 덤프되므로 말투가 확 달라져서 청중에게 티가 난다. 첫
  리허설은 14턴 중 4턴이 그랬고(T2·T7·T11·T12), 2차는 1턴(T8b)이었다. **넷 다 원인이
  «검증기가 옳은 답을 거부»였고 전부 고쳤다** — 질문 수치 되받기(T2), 재료에 없는 것을
  요구한 답변 형태(T13), 표의 행 이름 표기(T8b). 남는 턴이 있으면 `--show-llm` 으로
  버려진 생성문을 직접 보고, 그 문장이 **맞는지부터** 판단한다 — 맞으면 고칠 곳은
  질문이 아니라 검증기다.
- **고객을 연 첫 턴(T4·T13)이 유난히 느리면 브리핑 생성이 대화에 끼어든 것이다.**
  `customer` 도구는 브리핑 화면과 같은 산출(`strategy_agent.propose`)을 읽는데, 캐시가
  비어 있으면 AI 브리핑 생성(LLM 호출 11회)까지 그 턴이 떠안는다. Streamlit 화면은 앱을
  띄울 때 12명 전부 미리 생성하므로 — **발표 전에 앱을 미리 띄워 두면** 시연 중에는 이
  비용이 없다. `reps --demo` 도 고객 블록을 여는 시점에 같은 생성을 먼저 돌린다 — 대화
  턴의 시간과 섞이지 않는다. 시간이 궁금하면 `--time` 을 붙인다: 턴마다 「⋯ 답변까지
  N.N초」, 블록 머리에 「브리핑 화면 생성 N초」, 요약표에 시간 칸이 붙는다(진단용 —
  시연 화면에는 띄우지 않는다).
- **잔여일수는 시연 당일 기준으로 다시 계산된다.** ISA 만기 D-일수가 리허설과 달라진다.
  숫자를 대본에 외워 두지 말고, 고정하고 싶으면 `PENSION_TODAY=2026-08-24` 를 걸고 돈다.
- **상담 기록이 픽스처를 덮어쓰지 않게 한다.** 에이전트는 턴마다 상담이력을 남기고
  (기준서 §2), T5 가 읽는 것이 바로 그 저장소다. `reps --demo` 는 실행 전후로
  `session_data/` 를 되돌리지만 **Streamlit 화면과 `tests.debug` CLI 는 되돌리지 않는다** —
  그쪽으로 연습했으면 시연 직전에 픽스처를 되돌린다:

  ```bash
  git checkout src/session_data/       # 되돌리지 않으면 T5 가 «어제 연습»을 읽는다
  ```

- 답변이 **카드 원문 문어체**로 나오면(「■ 세액공제 — 한도 900만원 …」) 그건 생성문이
  폐기되고 근거 원문이 대신 나간 것이다. `--debug` 로그의 마지막 줄이 어느 검사에
  걸렸는지 말해준다. 어느 노드에서 왜 걸렸는지까지 파려면 검토용 전체 트레이스를 쓴다
  (`python -m tests.debug -c <고객id> --debug --show-llm "질문"`).
