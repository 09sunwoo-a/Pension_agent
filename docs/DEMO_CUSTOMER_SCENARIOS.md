# 고객별 대표 시나리오 — 대화형 에이전트 시연 라이브러리

고객 5명, 각자 **다른 능력 하나를 대표**하는 짧은 시나리오. 단일 고객으로 전체 흐름을
타는 대본은 `docs/DEMO_SCENARIO.md` 가 따로 있다 — 이 문서는 그 대본의 메시지 축
(A 근거 · B 계획 · C 경계)을 상속하되, **브리핑 에이전트의 데모 골든 케이스와 같은
고객으로 대화를 잇는 것**과 **고객을 바꿔가며 다른 장면을 꺼내는 것**을 위해 고객 단위로
쪼갠 판이다.

> 이 문서는 손으로 쓴다(생성물이 아니다). 「보이는 것」은 기대이지 보장이 아니다 —
> 문장은 매번 LLM 이 새로 쓰므로 리허설에서 확인하고 들어간다. **◇ 표시가 붙은 턴은 아직
> 실 LLM 으로 돌려보지 않았다**(2026-09-02 추가). 실행 — 시나리오 통째로
> (`tests/debug/reps.py::SCENARIOS`, 고객마다 한 세션·맥락 이어짐):
>
>     cd src && PENSION_TODAY=2026-09-01 python -m tests.debug.reps --scenario
>     cd src && PENSION_TODAY=2026-09-01 python -m tests.debug.reps --scenario 김서연 --debug
>
> 턴 하나만 따로 볼 때:
>
>     cd src && python -m tests.debug -c <고객ID> --debug "<질문>"
>
> `PENSION_TODAY` 를 거는 이유는 이수민 때문이다 — 아래 「공통」의 함정 ②.

## 어느 장면이 무엇을 보여주나

고객이 아니라 **능력**을 세로축에 놓은 표다. 아래 고객별 표는 「이 고객으로 무엇을
보여주지」에 답하지만, 「에이전트의 어떤 능력이 아직 안 나왔지」에는 답하지 못한다 —
시간이 모자라 무엇을 자를지도 여기서 정한다.

| 에이전트가 하는 일 | 어디서 보이나 |
|---|---|
| 고객을 열면 먼저 물어볼 것을 내민다 (추천 질문 칩) | 박정호 P1 · 송도윤 S2 · 송도윤 S5 |
| 한 질문에 재료를 여러 개 모은다 | 김서연 K2 · 박정호 P2 |
| 갈리는 값은 지어내지 않고 되묻는다 | 김서연 K3 → K4 |
| 답이 다음 화면으로 이어진다 (제안 → 승낙 → 딥링크) | 김서연 K5 → K5b |
| 먼저 제안하고 승낙받아 보여준다 | 이수민 L4 → L4b |
| 고객에게 나갈 것을 준비하되 결정은 직원에게 넘긴다 | 송도윤 S5 → S5b |
| 순서가 어긋나면 권하기 전에 막는다 | 박정호 P4 |
| 흔한 오해를 원문 근거로 끊는다 | 이수민 L3 |
| 지난 기록을 오늘 제안의 명분으로 쓴다 | 송도윤 S2 |
| 같은 질문에 고객이 다르면 다른 답 | 송도윤 S4 ↔ 정민석 J1 |
| 없는 것은 없다고 한다 | 송도윤 S6 |
| 값을 계산해 답한다 | 이수민 L5 |

## 김서연 — 타행 ISA 8,000만원, 만기 한 달 앞

**원장 재료**: ISA만기자금(IRP 외부) 8,000만원 · 만기 2026-09-30 · 타행 / 세액공제
잔여한도 500만원(당해 납입 400만원) / 예금 2,800만·단기채 1,500만·현금성 200만 /
디폴트옵션 설정 / 위험중립형. **과거 상담 기록은 없다** — 추천 질문 칩이 안 뜨는 것이
정상이고, 기록 있는 고객(박정호·송도윤)과의 대비가 그 자체로 장면이다.

| | 질문 | 보이는 것 | |
|---|---|---|---|
| K1 | 「이 고객 어떤 상황이야?」 | ISA 만기(D-일수는 계산값) · 잔여한도 · 보유구성이 근거 카드와 함께 | A |
| K2 | 「ISA 만기자금을 IRP로 옮기면 뭐가 좋아?」 | 60일 골든타임 · 전환금 10%(최대 300만원) 추가 한도 · 49.5만원 추가 환급 수치 · 현장 화법(「본부 확정 지침이 아닙니다」 표시) | A |
| K3 ★ | 「고객이 8천만원 전부는 부담스럽다는데, 일부만 옮기면 세액공제는 어떻게 돼?」 | **답 대신 되묻기** — 총급여 5,500만원 이하/초과(공제율이 갈리는 미확인 값) | **C** |
| K4 | 「초과야」 | 되물은 갈래(13.2%)로 이어서 계산 | B |
| K5 | 「입금은 몇 번 화면에서 해?」 | [01-12-213] ISA 만기자금 입금 + **「화면 열어드릴까요?」 연계 제안** | B |
| K5b ◇ | 「응, 열어줘」 | 딥링크 `mystar-link://scnNo=0112213&mode=D` | C |

K3 의 되묻기가 이 고객 시나리오의 핵심 장면이다(브리핑 문서가 「고객과 확인」으로 남겨둔
값을 대화형이 실제로 확인하러 온다). K5b 는 「여는 것까지가 에이전트 몫이고 실제 처리는
직원이 그 화면에서 한다」를 짧게 보여주는 자리다.

**실측 상태**: K2·K3 은 gemma(`LLM_PROVIDER=gemma`)로 실측했다. **K4 는 미실측이다** —
리허설 당시 분당 토큰 한도(429)에 걸려 한 번도 답을 받지 못했다. K5b 도 미실측이다.

**K4 를 「초과야」로 쓰는 이유**: 아래 공통 함정 ③. 「5,500만원 초과야」라고 쓰면
`tax_credit` 도구가 그 5,500만원을 **추가 납입액**으로 읽는다. 되물은 갈래를 고르는 답은
금액 없이 쓴다(기준서 §5 — 「2번째꺼」·「후자」도 같은 형태다).

**피할 것**: 「신한은행 ISA」라고 묻지 않는다 — 원장은 기관구분 「타행」까지만 안다
(브리핑 데모 문서의 은행 실명은 이 원장 스키마에 없다). 「이 고객 ETF 관심 있다던데」도
금지 — 앱 조회 이력은 원장에 없는 재료다.

## 박정호 — 퇴직금 1억 5천을 통장으로 받은 고객

**원장 재료**: IRP 2,000만원 전액 정기예금(만기 2027-03-10) / 연금개시 요건 충족·미개시 /
2026-08-20 콜 상담 기록 — 「8월 퇴직으로 퇴직급여 약 1억 5,000만원을 일반 입출금계좌로
수령. 당장 쓸 계획은 없는데 어디에 넣어둘지 고민」. **퇴직 사실과 1.5억은 이 발화에만
있다**(원장에 재직상태·타계좌 필드가 없다 — 브리핑 데모 문서가 말한 「보수적 버전: CRM
발화 경유」 경로 그대로).

> **전제 — 세션 시딩이 되어 있어야 한다.** 칩과 `history` 도구는 원장이 아니라 세션
> 저장소를 읽는다. 골든 3명을 원장에 합친 뒤 시딩을 다시 돌리지 않으면 이 기록이 세션
> 저장소에 없어서 **P1 이 통째로 죽는다**(칩도 안 뜨고 재료도 0건). 확인 방법은 아래
> 공통 함정 ①.

| | 질문 | 보이는 것 | |
|---|---|---|---|
| P1 ★ | (칩으로) 「지난 상담(8/20 · N일 전)에서 무슨 얘기 했지?」 | 8/20 콜 기록 — 퇴직금 1.5억 통장 수령 + 「어디에 넣어둘지 고민」 | A |
| P2 | 「퇴직금을 이미 통장으로 받았다는데, 지금이라도 IRP로 되돌릴 수 있어?」 | 수령일로부터 60일 이내 재입금 → 퇴직소득세 환급, 일부만도 가능 | A |
| P3 | 「절차가 어떻게 돼? 서류는 뭐가 필요해?」 | 과세이연정보 등록(먼저) → 입금 → 환급 신청 순서 + 원천징수영수증 + [06-12-501] 등 화면 연결 | B |
| P4 ★ | 「이 고객 연금개시 요건도 충족했던데, 개시까지 같이 진행하면 걸리는 거 없어?」 | **순서 경고** — 환급 완료 전에는 지급·연금설계 등록이 제한된다 · 환급 사이클(익월 10일) | **C** |

P4 가 이 고객의 핵심 장면이다: 배지(연금개시 요건충족 후 미개시)만 보면 개시를 권하고
싶어지는 자리에서, 에이전트가 과세이연 환급과의 **선후 충돌**을 먼저 세운다. 근거 카드는
proc.043(「퇴직소득세 환급 전에는 지급·연금설계 등록이 제한된다」)과 fact.k04.f47 이다.

**질문 문구가 이 장면을 가른다.** 처음에는 「개시도 같이 **권할까?**」였는데, 그러면 계획이
화법 축으로만 간다 — 실측(2026-09-02)에서 `customer → playbook → pitch` 를 부르고 절차·제도
도구를 아예 안 불러, 순서 경고가 든 카드 둘이 원장에 없었다. 답변이 그 얘기를 **할 수 없었고
지어내지 않은 것은 올바른 동작이다.** 「**걸리는 거 없어?**」로 바꾼 것은 계획을 제약 확인
축으로 돌리기 위해서다. 환급·과세이연을 직원이 먼저 말하지 않으므로 **찾아내는 것은 여전히
에이전트 몫**이고, 앞 턴(P2·P3)이 세워 둔 환급 절차 맥락을 「같이 진행하면」이 가리킨다.

바꾼 뒤 실측(2026-09-02)에서 계획이 `procedure` 를 부르며 질의를 이렇게 썼다 —
«퇴직금 IRP 소급 입금 후 연금개시 동시 진행 시 유의사항 및 제한 여부». proc.043 한 장으로
답이 섰고, 첫 문장이 「환급이 완료되기 전까지는 IRP 지급과 연금설계 등록이 모두 제한돼요」
였다. **직원이 환급을 한 마디도 꺼내지 않은 채 에이전트가 충돌을 찾아온 것**이 이 장면의
값어치다 — 발표자 멘트도 거기에 얹는다.

**진행 메모 — 화면 연계 제안이 P3·P4 두 번 붙는다.** 답변이 화면번호를 인용하면 자동으로
붙기 때문이다(P3 은 [06-12-501], P4 는 [01-12-213]). P4 는 승낙이 아니라 새 질문이므로 P3 의
제안은 **조용히 무효가 되고**(기준서 §10 — 제안은 그 자리에서만 유효하다), P4 의 제안은
시나리오가 거기서 끝나므로 답 없이 남는다. 둘 다 정상 동작이니 당황하지 말고 넘어간다.
딥링크를 실제로 열어 보이는 것은 김서연 K5b 에서 한 번이면 충분하다.

**주의 — 리허설에서 볼 것.**
- **P4 도구 줄에 `procedure` 나 `fact` 가 찍히는가.** 순서 경고는 그 두 종류의 카드에만
  있으므로(proc.043 · fact.k04.f47), 계획이 절차·제도 축을 부르지 않으면 이 장면은 성립하지
  않는다 — 문구를 바꾸기 전이 그랬다. `--debug` 의 「무엇을 찾아봤나」 블록에서 바로 보인다.
  덧붙여 `proc.043` 은 「연금개시」 어휘만으로는 검색에 잘 안 걸린다(실측 — proc.049·proc.051
  에 밀린다). 계획 질의에 「환급」·「과세이연」이 들어가야 닿으므로, 앞 턴이 그 맥락을 세워
  두는 것이 이 장면의 전제다. **P4 만 따로 떼어 물으면 안 나올 수 있다.**
- **답변이 이 고객에게 없는 상황을 상담 핵심으로 세우지 않는가.** 실측에서 「이번 상담의
  핵심은 … 만기 재운용 쪽」이 나왔는데 박정호 만기는 2027-03-10(D-190)이고 만기 요건도
  안 선다. 수치가 아니라 속성 단정이라 답변 점검이 원래 못 잡는 자리다(기준서 §6).

**피할 것**: 「퇴직금이 정확히 얼마야?」 — 원장 값이 아니라 고객 발화라 「약 1.5억」
이상으로 특정하면 안 되는 재료다. **중도해지 유불리와 연금수령한도를 계산시키는 질문**도
금지 — 그 둘은 아직 요건이 아니다(기준서 §13). 세액공제 환급액은 계산할 수 있다
(`tax_credit` 도구 — 이수민 L5 에서 쓴다).

| L1 | 「이 고객 왜 관리 대상이야?」 | 만기 임박 + 디폴트옵션 미등록 + 대기 현금 — 요건별 성립 근거 | A |
| L2 | 「만기 전에 미리 정해둘 방법 있어?」 | 자동 재예치 폐지 → 만기상품 예약변경(만기 1개월 전부터) — 지금이 그 구간 | A |
| L3 ★ | 「디폴트옵션을 등록하면 지금 있는 현금 1,000만원도 자동으로 굴러가?」 | **아니오** — 등록만으로 기존 현금성자산은 이동하지 않는다, 교체매매와 세트 | **C** |
| L4 | 「고객이 원치 않는 상품에 강제 가입되는 거 아니냐고 하면?」 | 거부감 해소 화법 + **「이 고객 «원리금보장상품 편중 · 디폴트옵션 미설정» 상태에 걸린 화법 2건, 연계해드릴까요?」** | A |
| L4b ◇ | 「네」 | 화면 ⑥⑦⑧ 이 자른 나머지 후보에서 이 고객 상태에 걸린 화법 2건 | **B** |
| L5 ◇ | 「300만원 더 넣으면 얼마 돌려받아?」 | 잔여한도 900만원 기준 계산 — 5,500만원 이하 49.5만원 / 초과 39.6만원, 구간은 원장에 없어 둘 다 | B |

L3 이 핵심 장면이다 — 「등록하면 알아서 되겠지」라는 흔한 오해를 원문 근거로 정확히
끊는다. L4b 는 **에이전트가 먼저 내밀고 승낙을 받는** 장면이다: 직원이 묻지 않았는데
답변에 끼워 넣는 것이 아니라 한 줄로 묻고, 승낙해야 보여준다. 제안 문구가 「무엇에
걸렸는지」를 밝히는 것도 함께 짚을 자리다(요건 이름은 코드가 아는 값이라 지어낼 수 없다).

L5 는 이 다섯 고객 중 계산이 가장 깨끗한 자리다 — 당해 납입 0원에 잔여한도가 한도
전액이라 「더 넣으면 얼마」가 온전히 보인다.

**피할 것**: 「현금성자산 금리 몇 %야?」 — `market/rates_demo.json` 자리표시자다(전체
대본의 피할 질문과 동일). 「6월에 만기된 1,000만원」이라는 표현도 쓰지 않는다 — 상환
이력은 원장에 없고 현금성자산 잔액만 보인다.

**주의 — 이 고객은 날짜를 탄다.** 만기 요건(`mat`)은 만기 30일 전부터 선다. 아래 공통
함정 ②.

판매중단펀드 보유(KB 퇴직연금 배당 8,000만) / 최근 상담 2025-10-06 — 「수익 난 상품은
유지, 현금성자산은 단계적으로 재투자하고 싶다」.

|---|---|---|---|

S2 는 타이핑하지 말고 칩을 누른다(기록 있는 고객에만 뜨는 것 자체가 장면). S5 도 칩이다 —
직원은 지금 어떤 세미나가 열려 있는지 모르면 물어볼 생각조차 못 하므로, **칩 문구 자체가
알림**이다. 관련도 0 인 폴백은 세지 않으므로 이 칩은 아무 고객에게나 뜨지 않는다.

**S5b 의 요점은 발송이 아니라 «수행하지 않는다»이다.** 에이전트가 붙이는 문장은
「발송해드릴까요?」가 아니라 **「발송 화면 열기, 연계해드릴까요?」**이고, 승낙해도 나가는
것은 딥링크와 화면에 넣을 문구뿐이다. 보낼지는 직원이 그 화면에서 정한다(기준서 §10 —
되돌릴 수 없는 대외 행위는 에이전트가 수행하지 않는다). 발표자 멘트도 그 경계를 짚는다:
「문구까지 준비해서 화면을 열어주고, 보내는 것은 사람이 합니다.」

S6 은 전체 대본 T12 와 같은 질문이다(그쪽에서 실측 완료). 이 문서 다섯 고객 중 유일하게
**모른다고 답하는 장면**이라 잘라내지 않는다 — 앞의 답들을 믿을 이유가 이것이다. 지식베이스
에는 「증권사 수수료 무료」 반론 화법은 있지만 **타행 수수료 표는 없다**(확인함). 첫 문장이
「타행 수수료 자료는 없어요」로 시작하는지만 보면 된다.

**진행 메모**: S3 이 화법 재료를 다루므로 그 턴 끝에도 화법 연계 제안이 붙는다. S4 는 새
질문이라 그 제안은 무효가 된다(박정호 P3→P4 와 같다). 승낙 장면은 이수민 L4b 에서 한 번
보여주므로 여기서는 넘어간다.

**주의 — 캘린더와 날짜를 탄다.**
- 당행 ISA 만기가 2026-09-20 이라 **시연일이 9/20 을 지나면 만기 경과 상태로 장면이 바뀐다**.
- S5 의 세미나(SEM-002)는 **9/10 에 끝난다.** 그 뒤에는 세미나가 빠지고 이벤트만 남는다

## 공통 — 리허설 체크

### 들어가기 전에 확인할 함정 넷

**① 상담 기록 시딩.** 박정호 P1 과 송도윤 S2 가 여기 달려 있다. 원장에 기록이 있어도
세션 저장소에 내려가 있지 않으면 칩이 안 뜬다.

```bash
cd src && python -m scripts.seed_sessions     # 멱등 — 없는 것만 심는다
python -c "from pension_agent.consult_agent import suggest; print(suggest.history_chips('168450-7293815'))"
```

기록 있는 고객은 박정호·송도윤·정민석이고, **김서연·이수민은 원장에 기록이 없어 칩이 안
뜨는 것이 정상**이다. 그리고 에이전트는 턴마다 상담이력을 남기므로, Streamlit 이나
`tests.debug` CLI 로 연습했으면 시연 직전에 픽스처를 되돌린다(`reps` 는 스스로 되돌린다).

```bash
git checkout src/session_data/     # 되돌리지 않으면 「어제 연습」이 지난 상담으로 읽힌다
```

**② 이수민은 날짜를 탄다.** 만기 2026-09-26 이고 만기 요건은 30일 전부터 선다. 실측:

| 오늘 | 잔여 | 만기 요건 |
|---|---|---|
| 2026-08-24 (`tests/__init__.py` 고정값) | D-33 | **안 선다** |
| 2026-08-27 | D-30 | 선다 (하한) |
| 2026-09-01 (골든 케이스의 D-25) | D-25 | 선다 |
| 2026-09-26 | D-0 | 선다 (상한) |

고정 날짜 그대로 돌리면 L1 의 「만기 임박」과 L2 의 「지금이 그 구간」이 안 나온다.
`PENSION_TODAY=2026-09-01` 이상으로 돌린다. 운영 CLI·Streamlit 실화면은 실제 날짜로 도므로
시연 당일에는 그대로 성립한다.

**③ 계산기는 질문의 첫 금액을 「추가 납입액」으로 읽는다.** `tax_credit` 도구는 계획 LLM 이
쓴 질의가 아니라 **직원이 친 말**에서 금액을 뽑는다(그게 맞는 설계다 — 재작성본은 숫자를
흘린다). 대신 질문에 다른 뜻의 금액이 있으면 그것을 납입액으로 읽는다. 그래서 되묻기의
답은 「5,500만원 초과야」가 아니라 **「초과야」**로 쓴다.

**④ 안내 콘텐츠는 캘린더가 있다.** 세미나는 하루짜리라 지나면 후보에서 빠진다. 지금
열려 있는 것은 `docs/DEMO_STATUS.md` §1 이 표로 갖고 있다 — 시연 주에 한 번 본다.

### 그밖에

- 날짜 파생값(D-일수·경과일)은 `today()` 기준 계산값이다. `tests.debug`·`reps`(CADR)는
  `PENSION_TODAY` 를 걸지 않으면 2026-08-24 로 고정되고, 운영 CLI·Streamlit 실화면은 실제
  날짜로 돈다. 실화면으로 시연한다면 **당일 아침에 한 번 돌려** 날짜가 만든 상태 변화
  (송도윤 ISA 9/20, 이수민 만기 9/26, 김서연 ISA 9/30)를 확인한다.
- gemma(무료 키)로 리허설할 때는 분당 토큰 한도(429)를 친다 — 턴 사이 1분 안팎 간격을
  두거나 `LLM_RETRY_ATTEMPTS` 를 올린다. 고객 카드가 큰 고객(송도윤·정민석)일수록 잘
  걸린다. 김서연 K4 가 미실측으로 남은 이유가 이것이다.
- **고객을 연 첫 턴이 유난히 느리면 브리핑 생성이 대화에 끼어든 것이다.** Streamlit 은 앱을
  띄울 때 미리 생성하므로 **발표 전에 앱을 미리 띄워 둔다**.
- `--debug` 를 붙이면 턴마다 「무엇을 찾아봤나 → LLM 이 몇 자 썼나」 로그가 답변 아래
  붙는다. **시연에서 띄울 것은 이것**이고, 도구가 여러 개 찍히는 턴(김서연 K2 · 박정호 P2)
  에서 한 번 띄우면 «에이전틱함»이 눈으로 보인다. 노드·게이트 트리를 그리는 전체 트레이스는
  진단 도구라 청중에게 보여줄 것이 아니다.

전체 대본(`DEMO_SCENARIO.md`)의 「시연에서 피할 질문」 중 아래는 그대로 유효하다.
