# market — 시황 소스 (자리만 확보)

> **상태: 미구현 플레이스홀더.** 시황 원천 API 규격이 정해지면 여기에 구현한다.
> 지금은 "시황이 이 디렉토리에서 관리된다"는 것만 구조로 표현한다.

## 역할

원천 피드(외부 API)를 **에이전트가 쓸 수 있는 지식**으로 정제하는 계층. 외부 API 규격을
이 디렉토리 안에 격리하고, 바깥에는 안정된 읽기 계약(`current()`) 하나만 노출한다.
(llm.py 가 LLM 프로바이더를 격리하는 것과 같은 원리)

```
[뉴스 전체 API]  (비정형·대량) ─┐
                                ├─→ market (정제/큐레이션) ─→ current()
[금리·사실 API]  (구조화) ──────┘                              │
                                                    ┌──────────┴──────────┐
                                              strategy_agent         bff /market
                                              (근거·사실로 소비)      (표출: 금리·브리핑)
```

## 소비자 둘 · 소스 하나

- **strategy_agent**: `current()` 를 고객 프로필과 같은 '입력 사실'로 받는다.
  금리·사실 → 숫자 레이어(정확), 뉴스 → 근거(rsn) 레이어(출처·일자 필수).
  **적합성 게이트를 우회하는 추천 동인이 되면 안 된다.**
- **bff `/market`**: `current()` 를 표출 위젯(상단 금리 티커·직원 브리핑)에 그대로 전달.
  표출에는 LLM 이 필요 없다.

pitch_agent 는 시황을 쓰지 않으므로 소비자에서 제외한다.

## 정할 것 / 이미 정한 것

지금 계약(`current()` 반환 스키마)만 고정하면, 정제 방식은 나중에 통째로 바꿔도
소비자 코드는 건드리지 않는다.

| 지금 고정 | 나중에 결정 (미정) |
|---|---|
| `current()` 반환 스키마 (`facts` · `briefs` · `as_of` · `sources`) | 뉴스 API·금리 API 실제 규격 |
| 소비자 둘이 `current()` 만 본다 | 뉴스를 LLM 으로 어디까지 정제할지 |
| 외부 API 규격은 이 디렉토리에서 격리 | 갱신 주기 · 큐레이션 모델 |

## 예정 구성 (구현 시)

```
market/
├─ __init__.py      current() — 정제된 시황 읽기 계약
├─ adapters/        외부 API 클라이언트 (뉴스 · 금리) — 규격 격리
├─ refresh.py       원천 → 정제 → 캐시 갱신 잡 (스케줄)
└─ data/market.json 정제 결과 캐시 (as_of · facts · briefs · sources)
```
