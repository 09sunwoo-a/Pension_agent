# 00. 전체 플로우 — 퇴직연금 사후관리 에이전트

> **v0.1** (2026-08-24) · 서비스 전체의 큰 플로우를 정의하는 기준 문서.
> 이후 번호 문서(01~)는 이 플로우의 각 단계를 채우는 방법론이다.

## 서비스 정의

**사후관리가 필요한 고객을 찾아 → 자산·상황 맥락을 분석해 → 적절한 솔루션과 화법을 생성하여 → 영업점 직원에게 제공하는 에이전트.**

- **사용자**: 영업점 직원 (1차 수혜자: 신입~중견)
- **대상 고객**: 당행 개인형IRP 보유 고객의 **사후관리** (신규유치·기업형 DB/DC는 범위 밖)
- **원칙**: 코어 로직은 일반론(어느 퇴직연금 사업자에게나 성립하는 방법론)으로 정제한다.
  은행 이익 전술(락인 유도·KPI 득점)은 코어에서 제외하고 별도 트랙으로 관리한다.

## 제품 구조

```
대시보드 (메인화면)
 └─ 오늘의 타겟리스트
     └─ [클릭] → 개인별 솔루션 화면 + 상담 대응 챗봇
                    └─ 장바구니 → CRM 기록 · 후속 일정
```

## 비즈니스 플로우: 5단계

```
1. 트리거 ──→ 2. 진단 ──→ 3. 대안 준비 ──→ 4. 개입 ──→ 5. 기록·연계
   (가설)      (검증+심화)     (제안 설계)      (상담 실행)    (다음 사이클의 입력)
      ↑______________________________________________________|
                          순환 구조
```

### 1단계. 트리거 — 주의 배분

- **질문**: 누구에게 지금 주의를 쓸 것인가? (왜 지금, 왜 이 고객인가)
- **본질**: 상태 읽기가 아니라 **비교와 정렬**. 행원의 시간은 유한하므로 모집단 전체에서 우선순위를 정한다
- **입력**: 전체 고객의 계좌 데이터 (저해상도 스캔)
- **출력**: 우선순위가 정렬된 고객 리스트 + 각 행의 "왜 지금" **가설**
- **제품**: 대시보드 — 오늘의 타겟리스트

진단으로 들어오는 **입구 3종**:

| 입구 | 설명 |
|---|---|
| ⓐ 조건식 스캔 | 아웃바운드 — 정량 트리거 조건을 전체 고객에 정기 실행 |
| ⓑ 이벤트/기한 | 상품 만기, 제도상 기한 등 시점이 정해진 사건 |
| ⓒ 인바운드 | 내점·문의 — 리스트와 무관하게 발생 |

### 2단계. 진단 — 종합 상태 읽기

- **질문**: 이 고객의 전체 그림은 무엇인가?
- **본질**: 대상이 한 명으로 정해진 뒤의 **풀 진단**. 트리거 조건만 보지 않고 전체를 읽는다
- **첫 작업**: 트리거 가설의 **검증(오탐 제거)** — 오탐이면 여기서 종료(접촉 안 함)
- **입력**: 고객 1명의 전체 계좌·이력 데이터 (고해상도)
- **출력**: 종합 상태 (자산 구성, 격차, 성향, 시계, 접촉 이력)
- **제품**: 개인별 솔루션 화면 (상단 — 고객 브리핑)

> 타겟리스트의 각 행은 **결론이 아니라 가설**이다. 클릭(1→2 전환)이 저해상도 → 고해상도 진단의 전환점이다.
> 진단·솔루션 로직은 트리거와 **독립적으로 실행 가능**해야 한다 (입구 ⓒ 대응).

### 3단계. 대안 준비 — 제안 설계

- **질문**: 무엇을 어떤 순서로 제안할 것인가?
- **본질**: 진단 결과를 제안으로 변환. 접촉 전에 재료를 손에 들고 시작한다
- **입력**: 진단 결과 + 이달의 상품·금리 풀 (월 단위 갱신)
- **출력**: 우선순위가 정해진 제안 (+예비) · 근거 · 예상 반론 대비
- **제품**: 개인별 솔루션 화면 (제안부)

### 4단계. 개입 — 상담 실행

- **질문**: 어떻게 말하고, 어디까지 말하는가?
- **본질**: 상태에서 출발하는 화법 + 갈림길은 고객에게 묻는 질문. 채널별 제약(컴플라이언스) 준수
- **입력**: 제안 패키지 + 상담 중 고객 반응 (실시간)
- **출력**: 합의/보류/거절 + 실행 경로 (비대면 URL / 내점 / 전담조직 연계)
- **제품**: 상담 대응 챗봇

### 5단계. 기록·연계 — 다음 사이클의 입력

- **질문**: 이 상담을 어떻게 다음 상담의 재료로 만드는가?
- **본질**: 상담 결과의 자산화. 이 단계가 있어야 사이클이 **순환**한다
- **입력**: 상담 중 합의·보류·거절 내역 + 행원이 챗봇에 입력한 내용
- **출력**: CRM 상담 기록 · 후속 일정(재접촉 예약) · 진행 추적
- **제품**: 장바구니 → CRM 연계

> 5단계의 출력(기록·예약)은 1단계(후속 일정 = 이벤트 트리거)와 2단계(과거 상담 이력 = 진단 재료)의 입력이 된다.

## 공유 자산 — 단계는 프로세스, 룰은 자산이다

단계(01~05)는 일의 순서이고, 조건식·액션은 단계들이 **공유하는 자산**이다.
같은 조건식("현금성 편중")이 1단계에선 트리거로, 2단계에선 진단 항목으로 재사용되므로,
단계 문서에 각자 정의하면 임계값이 어긋나는 드리프트가 생긴다. 정의는 한 곳([10_룰_카탈로그.md](10_룰_카탈로그.md))에만 둔다.

```
        ┌────────────────────────────────────────┐
        │  10. 룰 카탈로그 (단일 정의처)               │
        │  상태 판정 룰(R-): 조건식 저해상도/고해상도 쌍  │
        │  액션(A-): 실행 내용·제약·경로·재료           │
        │  연결: 룰의 후보 액션 필드 (N:M, 분기 조건)    │
        └───────┬───────────┬───────────┬────────┘
     트리거 승격 룰 │    전체 룰 │           │ 룰→액션 매핑
     (+우선순위·기한) │          │           │
            ▼           ▼           ▼
       [1. 트리거]   [2. 진단]   [3. 대안 준비]
       모집단 스캔    개인 정밀 평가  후보 생성+적합성 검증
```

- **1단계** = 트리거로 승격된 룰의 저해상도 조건식을 모집단에 배치 실행
- **2단계** = 전체 룰(+ 상담 중에만 알 수 있는 진단 전용 항목)을 고객 1명에 고해상도 평가 — 검증(오탐 제거)은 같은 룰의 고해상도 조건식 실행
- **3단계** = 발화된 룰들의 후보 액션을 모아 F계열(제약) 룰로 적합성 검증
- 그 외 공유 자산: 주기 갱신 재료(월간 상품·금리·포트폴리오 / 주간 시황 / 분기 부진 리스트), 화법 카드, 계산기, 사전고지 문구집

## 관통 원칙 (모든 단계 공통)

| # | 원칙 | 근거 |
|---|---|---|
| G1 | 수치는 **원 단위 금액 + 기준시점**과 함께 산다 — 비율보다 금액이 통하고, 틀린 수치는 민원이 된다 | 현장 다수 검증 |
| G2 | 모든 재료에 **신뢰 라벨** (본부공식 / 현장팁 / 대외공개=고객 제시 가능) | 현장팁-본부자료 상충 사례 실재 |
| G3 | 출력은 **완성형** — 지시("안내하세요")가 아니라 대사("고객님, ~됩니다"), 화면·순서까지 | 원자료가 이미 대사체 |
| G4 | **"하지 말 것"이 "할 것"만큼 중요** — 금지 용어·제외 조건·사전 고지를 항상 병기 | 실수는 곧 민원 |
| G5 | 진단·설득의 단위는 절대값이 아니라 **격차** (기준선과의 거리) | 기준선 병렬 제시 구조 |
| G6 | **위험 수준은 고객이, 상품은 은행이** 정한다 | 분기 질문 구조 |
| G7 | 재료의 **갱신 주기**를 시스템이 안다 (월간: 상품·금리·포트폴리오 / 주간: 시황 / 분기: 부진펀드 리스트) | 갱신 주기를 아는 것이 노하우가 된 현실 |

## 별도 트랙 (코어에서 제외)

은행 이익 전술은 코어 로직에서 제외하고 추후 「리텐션 전술」 트랙에서 별도 정리한다:
락인 상품 유도(실물이전 불가 상품 매수), KPI 가중치·득점 시기 전술, 계열사 이전 유도, 등급 락인 화법, 경품 유인 등.
